# RackTop UI/UX 审计报告（浅色与深色）

- 审计日期：2026-08-06
- 审计版本：RackTop 1.14.3（macOS）
- 审计范围：浅色（灰白）模式、深色模式、键盘与辅助技术语义、弹窗、侧栏现有排序行为（不做改造）、趋势图、进程管理、设置、添加服务器、终端和动效
- 审计依据：项目 `Agent.md`、`emil-design-eng`、`apple-design`、`review-animations`、`find-animation-opportunities`
- 审计方式：代码只读检查、macOS App 实机交互、远端测试进程验证

## 1. 总体结论

RackTop 已形成较稳定的工作型界面：信息结构清楚、卡片密度合理、颜色克制，终端、趋势、空闲算力和“我的进程”之间具有一致的视觉语言。标准深色模式的总览、趋势、告警卡片、存储图和添加服务器引导整体可用。

当前不建议直接将 UI 视为完全定稿。发布前应优先解决模态框键盘行为、弹窗定位、趋势默认指标和热力图灰色状态；其余问题可按优先级逐步处理。

动效审计结论：**Block**。主要原因不是动效过多，而是弹窗缺少完整退出状态和焦点隔离。本轮明确不改造侧栏拖动，现有鼠标拖动行为保持不变。

## 2. 跨主题问题

| 优先级 | 当前表现 | 修改建议 | 原因 |
| --- | --- | --- | --- |
| P0 | 弹窗打开后焦点仍可停留或移动到背景页面，`Tab` 能逃逸，部分弹窗不能用 `Escape` 关闭 | 建立共享 Modal 组件，统一实现初始焦点、焦点循环、背景 `inert`、Escape 和关闭后焦点恢复 | 当前 `aria-modal` 只有声明，没有形成真实模态行为；结束进程实机验证已复现 |
| P0 | 确认框按整个窗口居中，向左偏，并且相对顶部工具栏过高 | 让遮罩属于右侧 `.workspace`，在排除顶部栏后的工作区内容视口内居中 | 弹窗属于服务器工作区，不应把侧栏和顶部栏一起计算中心 |
| P1 | 详情标签都是普通 Tab 停靠点，没有方向键导航和 `tabpanel` 关联 | 使用 roving `tabIndex`、左右/Home/End、`aria-controls` 和 `role="tabpanel"` | 当前只实现了部分 ARIA tab 语义 |
| P1 | 大量运行信息使用 7-10px 字体，部分三级文字对比度偏低 | 操作信息至少 11px，主要次级文字 12px；仅非关键元数据使用 9-10px | 日志、进程命令、About 和热力图标签阅读负担较高 |
| P1 | 服务器状态和本人任务主要依赖彩点、图标与 tooltip | 把在线、失败、警告和本人任务写入可访问名称，并同时统计 CPU/GPU 进程 | VoiceOver 无法获得与视觉用户等价的信息 |
| P2 | `body` 全局禁止文本选择 | 只在导航、按钮和拖动控件禁选；错误、地址、日志和说明允许复制 | 运维工具中的服务器信息和故障文本应可直接选择 |
| P2 | 趋势范围切换时先清空分布数据 | 保留旧数据，并使用低干扰的“更新中”状态 | 避免把加载过程误解为真实缺失数据 |
| P2 | CPU 进程为空时仍显示较大的空块 | 单块为空时压缩为 80-120px；只有整页为空才使用大空状态 | 空内容不应占据主要阅读空间 |
| P2 | 设置滑块的系统蓝色轨道比其他控件醒目 | 使用低对比轨道，蓝色只用于已填充区域和活动滑块 | 保持监控工具安静、稳定的视觉性格 |
| P2 | `App.tsx` 同时承接高频状态、同步、告警、导航和弹窗 | 按服务器与页面拆分订阅，并缓存总览和历史组件；侧栏拖动保持现有实现 | 当前 5 台服务器稳定，但规模增加后存在广泛重渲染风险 |

## 3. 深色模式增量结论

深色模式的主文字、卡片边界、选中状态、蓝绿热力图、橙色告警和存储所有权颜色总体清晰。以下问题是在深色检查中新增确认的，不重复浅色模式已有结论。

| 优先级 | 当前表现 | 修改建议 | 原因 |
| --- | --- | --- | --- |
| P1 | `--surface-muted` 被热力图、分布图和存储图使用，但变量没有定义 | 分别定义浅色和深色的 `--surface-muted`，深色使用稳定的不透明灰色表面 | 缺失、未使用和空闲格子的背景会退化为透明，与卡片底色融合，灰色状态表达不稳定 |
| P2 | 深色配合系统“提高对比度”时，边框仍被统一改为黑色半透明 | 在深色主题下改用白色半透明高对比边框 | 黑色边框在 `#111214` 背景上反而更难辨认 |

## 4. 动效审计

现有进入动画的时长、缓动和 `prefers-reduced-motion` 支持总体合格。建议只处理以下高价值动效：

1. 弹窗和 Toast 增加 120-160ms 的退出状态，退出路径与进入路径一致。
2. 进程详情展开可使用不超过 180ms 的轻微透明度与位移过渡。

明确不建议增加动画的位置：实时曲线、热力图、日志刷新、详情标签切换、服务器状态变化、实时卡片排序。这些区域承载真实数据且操作频繁，动画会制造延迟或视觉误导。

## 5. 建议实施顺序

1. 建立共享 Modal 基础组件，同时修复弹窗工作区定位。
2. 定义 `--surface-muted`。
3. 统一最小字号、次级文字对比度、文本选择和空状态尺寸。
4. 最后补齐弹窗/Toast 退出动效并进行减少动态效果复测。

范围说明：侧栏拖动本轮不做优化、不迁移 Pointer Events，也不新增键盘排序；保留现有鼠标拖动实现。

本报告只记录审计结论和修改建议，不代表上述问题已经修复。
