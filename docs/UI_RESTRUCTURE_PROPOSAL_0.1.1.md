# RackTop 0.1.1 页面结构与交互优化方案

状态：等待确认，尚未执行

依据：`docs/HUMAN_REPORTED_BUGS.md` 第 2 部分

## 目标

让用户进入 RackTop 后先看到所有服务器的 GPU 状态，再按需进入单台服务器详情。详情页优先回答“显存是否可用、GPU 是否繁忙、是谁在运行任务”，其余指标由详情标签承载。

## 1. 主导航与默认页面

### 修改前

- “总览”实际展示当前选中服务器的详情概览。
- “GPU 总览”另设一个入口展示全部服务器。
- 两个入口的名称和信息层级容易混淆。

### 修改后

- “总览”作为应用默认页面，直接展示全部服务器 GPU 状态墙。
- 移除重复的“GPU 总览”主导航按钮。
- “空闲 GPU”保留为独立入口。
- 点击侧栏服务器或总览中的服务器卡片，进入该服务器详情。
- 从详情返回“总览”时回到全部服务器状态墙，不改变用户设置的排序。

### 主导航顺序

1. 总览
2. 空闲 GPU
3. 服务器列表

## 2. 服务器详情概览结构

详情页概览按以下顺序排列：

1. 核心数据
2. GPU 状态
3. CPU 状态
4. 可视化趋势
5. 当前进程

### 2.1 核心数据

顶部只保留四项快速判断数据：

- GPU 可用数 / 总数
- 总显存占用 / 总显存
- GPU 平均利用率
- 当前 GPU 进程数

### 2.2 GPU 状态

每张 GPU 卡片的信息优先级：

1. `MEM`：显存占用百分比和已用/总量，使用最大的字号和最明显的进度条。
2. `UTL`：GPU 核心利用率，作为次要指标。
3. 卡片底部展示 `MBW`、`PWR`、温度和进程数。

显存低于 `1%` 时继续按未使用处理并使用中性背景。GPU 核心利用率不会改变卡片的显存背景语义。

如果当前 SSH 用户有任务，继续使用“你”标记和用户强调色，但不覆盖显存状态和选中状态。

### 2.3 CPU 状态

CPU 模块只突出两项：

- CPU UTL
- 系统 MEM

Load、Swap 和当前用户 CPU 等详细数据继续放在“CPU”标签页。

### 2.4 可视化趋势

参考 `docs/assets/IMG_1.png`，使用 2×2 图表：

1. CPU UTL
2. 系统 MEM
3. GPU MEM
4. GPU UTL

窄窗口时自动变为单列。所有百分比图固定在 `0%–100%`，不使用会产生数值过冲的平滑插值。

### 2.5 当前进程

概览底部直接展示当前 GPU 进程表，至少包含：

- GPU
- PID
- 用户
- 命令
- GPU 显存
- CPU
- 运行时间

点击进程可展开详情。完整进程功能仍保留在“进程”标签页。

## 3. 详情标签职责

- 概览：快速判断资源状态和当前任务。
- GPU：单卡趋势、完整 GPU 指标与设备选择。
- CPU：CPU、内存、Load、Swap 等系统资源详情。
- 进程：完整进程列表和进程检查器。
- 历史：更长时间范围的趋势。
- 日志：采集与连接记录。
- 连接：SSH 配置、重连和删除服务器。

## 4. macOS GPU 总览瀑布流

### 当前问题

当前使用 CSS Multi-column 实现瀑布流。WebKit/Tauri 在卡片高度变化和刷新时可能出现列重排、顺序异常或布局跳动，而网页版表现正常。

### 修改方案

- 改用 CSS Grid + `ResizeObserver` 计算卡片行跨度，实现稳定的瀑布流。
- 宽窗口为双列，窄窗口自动变为单列。
- 卡片 DOM 顺序始终采用用户选择的排序结果。
- 数据刷新只更新卡片内容，不重置排序或滚动位置。
- 卡片之间统一使用 12px 间距，GPU 设备行内部继续使用 4px 间距。
- 尊重“减少动态效果”，布局变化不添加大幅位移动画。

## 5. 刷新动画

### 当前问题

后台自动采样和用户手动刷新共用同一个 `busy` 状态，因此“刷新全部”会在后台采样时持续旋转。

### 修改方案

- 将“正在采集”和“用户手动刷新”拆成两个状态。
- 只有用户点击“刷新全部”后，按钮图标才旋转。
- 后台自动采样不触发按钮动画，也不禁用按钮。
- 单台服务器“测试并重新连接”只在该操作执行期间旋转。
- 保留服务器级单飞保护，避免自动采样和手动刷新产生重复 SSH 请求。

## 6. 不包含在本方案中的改动

- 不改变 SQLite 数据结构。
- 不改变已有服务器或 SSH 认证配置。
- 不改变显存低于 `1%` 按未使用处理的规则。
- 不为“寻找空闲 GPU”增加新的自定义选项。
- 不移除 GPU、CPU、进程、历史、日志和连接标签页。

## 7. 验收标准

- 启动后默认进入全部服务器 GPU 总览。
- 主导航不再同时存在“总览”和“GPU 总览”两个含义重叠的入口。
- 详情概览严格按“核心数据 → GPU → CPU → 四图表 → 当前进程”排列。
- GPU 卡片以 MEM 为第一视觉层级，UTL 为第二层级。
- macOS 和浏览器均保持稳定双列瀑布流，排序结果一致且刷新不跳列。
- 只有主动点击“刷新全部”时出现旋转动画。
- 自动采样期间内容持续更新，筛选、排序、所选服务器和滚动位置不丢失。
- 前端测试、Rust 测试、生产构建、浏览器回归和 macOS 原生回归全部通过。
