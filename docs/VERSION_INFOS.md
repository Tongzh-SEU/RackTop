# RackTop 版本信息

本文档记录 RackTop 各版本的用户可见变化、验证范围和发布注意事项。最新版本始终位于最上方。

## 1.3.0 — 空闲算力预约提醒

- 修改时间：2026-08-04 03:47:35 +08:00
- 发布日期：2026-08-04
- 发布阶段：功能版本（正式定稿）
- 桌面平台：macOS、Windows
- 升级类型：兼容更新；启动时自动创建预约数据表，不修改现有服务器、筛选条件或历史曲线

### 版本概述

RackTop 1.3.0 为“寻找空闲算力”增加条件预约。用户可以保存当前 GPU、CPU、进程、型号、持续时间和标签条件；应用在后台继续监测，条件稳定满足后发送包含服务器名称与 GPU 编号的系统通知。本版本同时分离高频状态刷新和历史曲线采样，扩展 GPU/CPU 进程及父子关系显示，并修复空闲显存边界判断及无标签卡片高度不一致问题。

### 新增功能

- “空闲条件”标题栏在“重置”左侧增加“预约”入口；即使当前已有符合条件的 GPU，也可以创建预约。
- 预约支持名称、2 小时/今天/24 小时/一直有效期限，以及“通知一次并结束”或“通知后继续监测”两种策略。
- 当前已符合条件的 GPU 在创建时保存为已知基线，不会立即重复通知；新的符合设备或退出后再次符合的设备才会触发。
- “当前快照”预约必须连续满足 30 秒；选择 5/10/30/60 分钟持续条件时沿用对应历史窗口判断。
- 通知标题使用具体服务器显示名和 GPU 编号，例如“3 * A100 · GPU 2 预约条件已满足”；正文显示可用 GPU/CPU 内存和可选物理位置。
- 点击预约通知会打开对应服务器的 GPU 详情；顶部铃铛提供预约列表，可编辑、暂停、恢复或删除预约。
- 预约持久化到本地 SQLite，应用重启后仍可恢复；完全退出应用期间不执行监测。
- 进程采样同时采集 GPU 与 CPU 任务，并记录 PID、父 PID、用户、命令、CPU、内存和运行时间；CPU 区块只保留 RSS 内存严格大于 1 GB 的 GPU 直接子进程，以及当前有 CPU 占用且占用最高的 12 个非系统用户进程组主进程。
- CPU 任务统一过滤常见后台服务，包括 nvitop/nvtop、VS Code/Cursor Remote、Codex、Claude、JetBrains Remote、用户桌面与音频会话，以及 Tailscale、ZeroTier、OpenVPN、WireGuard、Clash/Mihomo、sing-box、V2Ray/Xray、Cloudflare Tunnel 等常见 VPN/代理进程。
- 服务器“概览”和“进程”页都按 GPU、CPU 两个上下排列的区块显示进程；关系标签可直接识别“GPU 0 · PID 21312 的子进程”，GPU 父进程一侧也会显示 CPU 子进程数量或 PID。
- 概览复用紧凑进程模块并限制每块前 5 行，完整进程页复用同一模块展示全部采集结果和统一详情检查器。
- 点击进程后，详情在所选行正下方内联展开，不再脱离上下文显示在 GPU 与 CPU 两个区块之后。
- GPU 表将设备编号与 PID 合并为 `GPU · PID` 首列，使关系、用户和命令列采用与下方 CPU 表一致的紧凑排布。
- GPU/CPU 进程表增加受控的远程结束入口：只有当前 SSH 用户自己的进程组主进程可以勾选，其他用户进程与子进程不提供结束操作。
- 结束进程采用两阶段确认；第二阶段必须输入目标 PID，显示的 PID 可点击自动复制并原位提示“已复制”。Rust 后端会重新核对远端进程所有者与进程组主进程身份，再依次发送 TERM、等待、KILL 并清理残留子进程。
- “当前进程”摘要显示总进程数，副文案明确区分 GPU 与 CPU 进程数量，避免将 `12 CPU` 误解为 CPU 核心数；设置项同步更名为“进程刷新”。
- GPU 进程采样增加 NVIDIA `pmon` 的进程级 SM 活跃率；概览 GPU 卡片在 MBW 右侧显示所有已采样进程汇总的 `SM` 百分比，未采样时显示 `0%`，选中 GPU 或展开进程详情可查看各 PID 的 SM 百分比。

### 优化内容

- “算力总览”服务器卡片与单台服务器“概览”页的 GPU/CPU 状态目标刷新间隔缩短到 0.5 秒；其他页面和后台窗口继续使用既有采样间隔。
- 高频状态采集通过独立标志跳过历史写入，曲线仍按服务器原采样间隔记录并读取。
- 有标签和无标签的空闲 GPU 卡片都保留固定标签区域，卡片内容顶部保持对齐。
- 进程表将命令设为弹性主列，GPU/PID、关系、用户、显存、CPU 与运行时间采用稳定列宽；左侧选择位与区块图标对齐，长命令优先使用此前空置的横向空间。

### 修复内容

- 空闲条件筛选与卡片显示统一使用 0.1 GB 精度；显示 40.0 GB 的设备在筛选 40 GB 时不再错误标记为不可用。

### 保持不变的行为

- 预约只负责监测和通知，不会锁定 GPU，也不能阻止其他用户使用资源。
- 高频状态刷新不增加历史曲线采样点，GPU 与 CPU 进程仍按独立的较慢间隔刷新。

- 已执行 `git diff --check`，当前差异未发现空白错误。
- Rust 单元测试 16 项通过，包含进程组主进程标记、服务过滤和安全终止脚本回归测试。
- 已在 A100 服务器只读验证 `nvidia-smi pmon -c 1 -s um`：活跃计算进程返回 `SM 99% / MEM 81%`，空闲设备或不支持的进程返回空值；验证过程中未结束任何服务器进程。
- TypeScript 全量检查与 Vite 生产构建通过；生产包仍有超过 Vite 500 kB 建议阈值的提示。
- macOS Tauri Release 应用构建通过；`CFBundleShortVersionString` 与 `CFBundleVersion` 均为 `1.3.0`，ad-hoc 签名严格验证通过。
- 最新 DMG 已生成并通过 `hdiutil verify`，SHA-256 为 `cbe43536973c423f0f29cfc5059c2479917f0f9a9cd726b4fb7f338682d78e3b`。
- 已启动最新 Release App 检查真实 A100 服务器：概览卡底部显示 `MBW 81% · SM 47%`，无采样设备显示 `SM 0%`；选中 GPU 后显示 `PID 2146705 · SM 19%`。SM 数值随单次采样变化，界面未将其描述为算法效率。
- 已检查完整进程页：命令列使用剩余横向空间，GPU 与 CPU 区块上下排列，A100 服务器的 nvitop、VS Code、Codex、Claude、VPN 等后台进程未进入 CPU 任务列表。

### 已知事项

- 当前真实服务器没有属于当前 SSH 用户且为进程组主进程的可结束任务，因此未在生产 App 中执行最终结束操作，也未为测试制造远程进程；资格显示由前端测试覆盖，所有者和进程组身份由 Rust 后端测试覆盖。
- 结束进程确认框的 PID 点击复制与“已复制”状态已完成代码路径检查；因上述真实数据条件，本次未在生产 App 中打开该确认框。
- Windows 安装包仍需在真实 Windows runner 上构建验证。
- 完全退出 RackTop 后预约无法继续监测；菜单栏后台运行不受影响。

### 升级说明

可从 1.2.0 直接升级；应用会自动创建独立的 `idle_reservations` 表，现有服务器配置、保存的空闲条件与历史曲线保持兼容。

## 1.2.0 — 服务器物理位置与界面布局优化

- 修改时间：2026-08-04 01:22:28 +08:00
- 发布日期：2026-08-04
- 发布阶段：功能版本
- 桌面平台：macOS、Windows
- 升级类型：兼容更新；无需迁移服务器配置、筛选条件或历史数据

### 版本概述

RackTop 1.2.0 新增服务器物理位置，方便在设备掉线或需要现场重启时快速找到机房、机架和机位。本版本同时修复内容滚动条侵入顶部标题区、macOS 连续窗口拖动不稳定与服务器状态墙留白问题，并提升空闲条件的字号可读性。

### 新增功能

- 编辑服务器时可填写独立的“服务器位置”，用于记录实验室、机房、机架和 U 位等物理信息。
- 物理位置在服务器状态墙、服务器详情标题和 SSH 连接信息中显示，并可通过侧栏搜索。
- `SSH Config 别名` 与物理位置保持独立；别名仅在选择 `SSH Config` 认证方式时显示，不会因填写物理位置而改变 SSH 连接目标。
- SQLite 启动时自动为既有服务器增加可空的 `location` 字段，旧服务器、快照与历史数据保持不变。

### 修复内容

- 将顶部标题栏与主内容滚动容器分离，滚动条现在仅从 `78px` 高的标题栏下方开始。
- 滚动条轨道改为透明，滑块默认使用低对比度半透明颜色，仅在鼠标进入内容区时轻微增强。
- 空闲条件的标题、说明、字段标签、输入文字和底部摘要统一提升一档字号，改善高分辨率屏幕上的可读性。
- 服务器状态墙启用稠密网格回填，同一列的下一张卡片会紧接在较短卡片下方，不再因另一列卡片较高而留下大块空白。
- 服务器详情页顶部信息区与固定标题栏之间增加 `16px` 外间距，状态、更多操作和标签栏不再紧贴顶栏，并与总览、空闲算力页面保持一致。
- 实时趋势中的 CPU、系统内存、Swap、GPU 利用率与 GPU 显存曲线增加稳定身份；刷新时 ECharts 复用既有曲线并更新数据点，不再将整组曲线删除重建造成抽动。
- 服务器侧栏摘要从单独显示 CPU 利用率改为 `GPU 数量 + 总显存使用率 · CPU + 系统内存使用率`，例如 `3 GPU 30% · CPU 20%`；多张不同容量 GPU 按总已用显存除以总容量计算。
- 设置中的“个人占用强调色”更名为“我的任务标记色”，并明确说明它仍用于显存光标、当前用户任务标签和侧栏提示。
- 设置中的“外观”移至首位；设置标题和底部保存栏保持固定，中间内容独立滚动，滚动条不再侵入顶部区域，并使用与主内容一致的低对比度半透明样式。
- 编辑服务器弹窗将字段区与操作栏拆分；编辑服务器与设置弹窗的操作栏现在都使用和弹窗本体一致的材质并固定衔接底边，较矮窗口只滚动中间内容，不再显示为带四周留白的独立白框。
- 主顶栏和侧栏标题区从 `data-tauri-drag-region` 改为官方 `getCurrentWindow().startDragging()` 实现，并授予最小的 `core:window:allow-start-dragging` capability。
- 窗口拖动仅响应鼠标主键单击，刷新、通知、输入框等交互控件不会被拖动手势拦截。

### 保持不变的行为

- 顶部标题栏保持固定，页面内容、卡片顺序、筛选条件与数据采集行为不变。
- 本次不添加滚动或窗口动画，不改变现有减少动态效果设置。

### 验证记录

- 前端单元测试 22 项通过，Rust 单元测试 13 项通过。
- TypeScript 检查与 Vite 生产构建通过。
- macOS 1.2.0 Release 应用构建通过；短版本号与构建版本号均为 `1.2.0`，arm64 `RackTop.app` 为 13 MB，使用 ad-hoc 签名且未配置开发者 Team。
- 本地浏览器在 `1280×620` 视口强制滚动：顶标题栏边界为 `0–78px`，内容滚动容器边界为 `78–620px`，且 `scrollHeight 813 > clientHeight 542`，确认滚动条不再进入顶部区域。
- 本地浏览器使用四张 `420px / 260px / 260px / 260px` 不等高卡片实测，左右两列的上下间距均为 `12px`；右列下一张卡片在短卡后立即回填。`1000px` 宽视口下两张服务器卡片仍按原顺序回退为单列。
- 空闲条件最终计算字号为标题 `12px`、说明 `9px`、字段标签 `10px`、控件 `11px`、底部摘要 `9px`；`1000px` 宽视口下三列布局无文字溢出。
- 编辑服务器弹窗在 `1280×720` 视口下，操作栏左右边界与弹窗内容边界均为 `311–969px`，底部与弹窗内边界同为 `641.8px`；在 `1000×560` 视口下字段区 `scrollHeight 430 > clientHeight 360`，滚动后操作栏仍固定在 `466–527px`。服务器位置持续可见，`SSH Config 别名` 仅在对应认证模式下显示。
- 实时趋势回归测试确认 CPU、系统内存、Swap、GPU 利用率和 GPU 显存曲线均生成稳定且互不冲突的 ECharts `series.id`，`replaceMerge` 刷新会复用既有曲线。
- 侧栏浏览器实测显示 `3 GPU 40% · CPU 12%` 与 `2 GPU 0% · CPU 10%`，现有宽度下无截断；不同容量 GPU 的总显存占比加权测试通过。
- macOS 开发应用已启动并读取真实服务器界面；自动连续拖动时与用户同时操作 Release 应用发生冲突，第二次拖动未能完成自动化确认。

### 已知事项

- 需用最终 1.2.0 Release 应用手动连续拖动两次，确认 macOS 原生窗口行为。
- Windows 安装包仍需在真实 Windows runner 上构建验证。
- 前端生产包仍有超过 Vite 500 kB 建议阈值的提示，不影响本次滚动与窗口拖动修复。

### 升级说明

可直接从 1.1.0 升级到 1.2.0；应用会自动增加服务器位置字段，SSH 认证、空闲条件和 SQLite 历史数据均保持兼容。

## 1.1.0 — 保存空闲算力条件

- 修改时间：2026-08-04 00:18:24 +08:00
- 发布日期：2026-08-04
- 发布阶段：功能版本
- 桌面平台：macOS、Windows
- 升级类型：兼容更新；无需迁移服务器配置或历史数据

### 版本概述

RackTop 1.1.0 让空闲算力筛选成为应用级状态。侧栏数量与结果页现在始终使用同一套空闲条件，并在条件变化时即时同步；用户选择的条件会保存在本机，重新打开或刷新应用后无需重复设置。

### 新增功能

- 自动保存 GPU MEM、CPU MEM、进程占用、GPU 型号、CPU 型号、持续时间和服务器标签七项空闲条件。
- 应用启动或页面刷新时恢复上次使用的条件；点击“重置”会恢复并保存默认条件。
- 持久化数据使用带版本号的本地键保存，不上传服务器，也不改变现有 SSH、SQLite 或监控配置。

### 修复内容

- 修复修改空闲条件后，侧栏“空闲算力”数量仍按旧 GPU 空闲阈值计算的问题。
- 侧栏数量、全局摘要和空闲算力卡片现在共享同一判定结果，筛选变化后立即更新且不播放额外动画。

### 验证记录

- 前端单元测试 19 项通过，其中新增空闲条件解析、异常值回退、设备可用性及型号/标签范围测试；Rust 单元测试 12 项通过。
- 本地浏览器实测将“进程占用”从“无人占用”改为“不限”后，结果从 `3 张可用` 即时变为 `5 张可用`，侧栏数量同步从 `3` 更新为 `5`。
- 刷新页面并等待服务器采样后，侧栏仍显示 `5`；重新打开空闲算力页面，“不限”保持选中且结果仍为 `5 张可用`。
- TypeScript 检查、Vite 生产构建与 macOS Release 应用构建通过；短版本号和构建版本号均为 `1.1.0`，最终 `RackTop.app` 为 13 MB。

### 已知事项

- Windows 安装包仍需在真实 Windows runner 上构建验证。
- 前端生产包仍有超过 Vite 500 kB 建议阈值的提示，不影响筛选保存与计数同步。

### 升级说明

可直接从 1.0.1 升级到 1.1.0；首次启动使用既有默认条件，之后自动记住用户的选择。

## 1.0.1 — 扩大 macOS 窗口拖拽区域

- 修改时间：2026-08-03 23:35:54 +08:00
- 发布日期：2026-08-03
- 发布阶段：Bugfix
- 桌面平台：macOS、Windows
- 升级类型：兼容更新；无需迁移配置或历史数据

### 版本概述

RackTop 1.0.1 修复 macOS 原生应用顶部只有少量空白位置可以拖动窗口的问题，并完善服务器删除与 SSH Config 导入流程。侧栏交通灯安全区、品牌区域、页面标题及顶部操作区的非交互空白现在共同组成连续的窗口拖拽区域；重复连接会在导入前被识别并明确提示。

### 本版本修改

- 将侧栏顶部的交通灯安全区与 RackTop 品牌区域合并为完整拖拽区域。
- 将主内容顶部标题、刷新状态文字及按钮之间的空白纳入拖拽区域。
- 刷新、通知、导航等交互控件继续保持可点击，不会被窗口拖拽手势拦截。
- 浏览器版本的布局与交互行为保持不变；拖拽标记仅由 Tauri 原生窗口识别。
- 导航、标题、指标和按钮等应用界面文字默认不可选，避免拖动或快速操作时产生文字选区；输入框、日志、命令、连接地址和 SSH 指纹仍可正常选择复制。
- 服务器删除改用 RackTop 内置确认对话框，明确展示将删除的连接目标、本地历史数据范围及不会影响远程服务器的说明，并在失败时保留对话框显示错误。
- SSH Config 导入按“用户名、主机地址、端口”识别重复连接；已存在或配置内重复的条目会禁用选择、标记“已存在”，并显示跳过数量。
- 后端保存接口同步拒绝重复连接，避免绕过导入界面后写入重复服务器；不同用户名或端口仍可作为独立连接保存。
- 总览与“空闲算力”页面在顶部标题栏后明确保留 `16px` 外间距，使标题栏和首个信息模块之间的层级更清楚；服务器详情页布局保持不变。

- 查看 GPU 利用率、显存、温度、功耗，以及 CPU、内存、Swap 和 Load。
- 查看 GPU 进程的用户、PID、命令、显存、CPU 占用和运行时长，并突出当前 SSH 用户。
- 将所有服务器组织为 GPU 状态墙：一台服务器一个瀑布流区块，仅展示 GPU 与 CPU 摘要，点击区块进入服务器详情。
- GPU 状态墙支持按名称、状态、GPU 数量、利用率或空闲数量排序，并记住用户的排序设置。
- 空闲 GPU 页面支持按利用率、可用显存、持续时间、GPU 型号和服务器标签筛选。
- 使用 SQLite 保存历史数据，支持趋势图、自定义采样间隔、趋势窗口和历史保留期。
- 支持系统托盘和桌面通知，可提示服务器离线、GPU 高温、GPU 空闲、显存释放、持续满载和任务退出。
- 支持跟随系统的浅色/深色主题、减少动效和当前用户强调色。
- 浏览器开发模式内置双服务器演示数据，便于不连接真实服务器时进行本地界面验证。

### 本版本优化与修复

- 修复数字筛选输入无法删除 `0` 的问题，清空后可直接输入新数值，例如 `20`，不会变成 `020`。
- 空闲 GPU 筛选默认使用当前快照即时返回；只有持续时间条件需要查询历史窗口。
- 修复筛选结果短暂出现后消失的问题，筛选条件在数据刷新期间保持有效。
- GPU 状态墙以显存占用作为卡片背景的主要状态语义，GPU 核心利用率仅作为辅助数值强调。
- 显存占用低于 `1%` 时按未使用处理并显示为 `0%`，使用中性背景，避免少量系统进程造成误判。
- 显存占用 `1%–49%` 使用蓝色提示，`50%–84%` 使用橙色提示，`85%–100%` 使用红色提示。
- 对采集到的百分比进行 `0%–100%` 边界限制，避免界面显示异常数值。

### 详情与连接能力

服务器详情包含概览、GPU、CPU、进程、历史、日志和连接页面。Host Key 未确认时不会自动接受；指纹发生变化时会阻止连接。密码不会写入命令行、日志或 SQLite，只保存在当前会话内存或系统凭据存储中。

当 Ubuntu/Debian 服务器缺少 NVIDIA 驱动时，RackTop 可以提供诊断和安装协助。应用不会自动执行 `sudo`，只有在用户连续确认后才会尝试通过免交互 `sudo -n` 安装。
