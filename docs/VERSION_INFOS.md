# RackTop 版本信息

本文档记录 RackTop 各版本的用户可见变化、验证范围和发布注意事项。最新版本始终位于最上方。

## 1.8.1 — 修正存储分布与侧栏排序

- 修改时间：2026-08-05 18:27:27 +08:00
- 发布日期：2026-08-05
- 发布阶段：Bugfix / 内部预览
- 桌面平台：macOS、Windows
- 升级类型：兼容升级；不需要迁移配置或历史数据。

### 版本概述

修正 1.8.0 存储空间将 EFI、系统伪文件系统和容器内部挂载当作数据盘的问题，补齐当前用户、其他用量和空闲容量的颜色语义。同时修正 GPU 使用分布的格子密度、趋势页顺序，以及 macOS App 中侧栏拖动无预览、松手无反应的问题。

### 优化内容

- 存储采集补充当前 SSH 用户容量；优先统计用户主目录，并识别其他数据挂载下的同名用户目录。
- 存储华夫饼使用深绿表示当前用户、浅绿表示其他占用、灰色表示空闲，图例直接显示各自 GB/TB。
- 存储网格调整为 `100 × 5`、每盘 500 格；GPU 使用时间和显存分布调整为 `38 × 5`、每图 190 格。
- GPU 用户色强度提高到资源热力图最高一级的约 `92%`；存储当前用户也使用同等深绿，其他用量降低到约 `38%`，形成明确的深浅层级。
- 趋势页固定按“资源热力图 → GPU 使用分布 → 存储空间”排列。
- 磁盘归属扫描与高频状态刷新解耦：每 15 分钟重新扫描一次，中间刷新复用上次结果。
- 本地采样和远端历史同步入库时持续维护小时级资源桶；趋势页再按当前时区将小时桶组合为 3 小时格子，避免点击页面后临时转换原始快照。
- 现有数据库升级时自动执行一次兼容回填，之后新增或覆盖快照都会增量更新对应小时桶。
- 终端正文左右各增加 `8px` 内边距，避免命令贴边，同时保持终端高度和窗口自适应行为不变。

### 修复内容

- 过滤 `/sys`、`/proc`、`/dev`、`/run`、`/boot/efi`、Snap、Docker、Podman 和 Kubelet 内部挂载，避免将 EFI 变量区和引导分区显示为用户数据盘。
- 侧栏排序从 macOS WebView 中不稳定的 HTML5 Drag and Drop 改为抓手启动、窗口级鼠标事件跟踪；拖动期间不重排 DOM，被拖动行连续跟随鼠标，相邻行只通过可中断位移让出空位，松手后一次性持久化。
- GPU 使用分布移除额外的覆盖提示条；网格以灰色格和“缺失”图例保留未采样时段，用户与“未使用”的图例百分比继续按实际已覆盖时间统计，避免被所选总范围稀释。
- 非零用户占用不足半个华夫饼格时仍保留一个低浓度的部分占用格，避免小任务在图中完全消失。
- 服务器初次失败和退避等待继续显示蓝色“连接中”，连续第 3 次失败后转为红色“离线”；手动刷新开始时始终先显示蓝色。
- 正常在线服务器执行 0.5 秒静默采样时保持绿色，不再在每次请求开始时短暂切换为蓝色。
- 趋势页不再扫描和解析全部原始快照，改为读取后端预先维护的小时桶；当前时区对齐和 3 小时平均值仍保持不变。
- 终端“正在连接”状态点由黄色改为蓝色，与服务器连接状态语义保持一致。

### 验证记录

- 前端 Vitest：20 个测试文件、74 项测试通过，覆盖在线静默采样状态稳定性、连接失败颜色阈值、15 分钟磁盘采样、缺失时段灰色格、存储归属和侧栏排序算法。
- TypeScript 与 Vite 生产构建通过；Rust 单元测试 31 项、`cargo check` 通过。新增覆盖同时间点覆盖写入不重复计数、旧数据库小时桶回填，以及远端历史同步写桶。
- 使用真实 `3 * A100` 数据库测量：约 `38,821` 条快照回填为 `61` 个小时桶；release 下兼容回填约 `1.64 秒`，后续趋势查询约 `0.24 ms`。
- 使用两台现有服务器执行只读 `df` 过滤验证，未修改远端数据或配置。
- 从仓库最新 `dist` 构建并临时签名 `RackTop.app`，通过 `codesign --verify --deep --strict`；在 macOS App 内完成两次真实侧栏拖动、落位和持久化验证，并恢复原服务器顺序。
- 在 macOS App 内检查趋势页：小时桶已在真实数据库生成，CPU、3 张 GPU、使用分布和存储完整显示；覆盖提示条已移除，缺失时段为灰色格，存储深浅绿可区分；终端左右内边距和蓝色连接中状态已生效。

### 已知事项

- 当前用户容量依赖该 SSH 用户对目录的读取权限；不可读目录不会被错误计入“你的”。
- `cargo fmt --check` 仍因本机 stable 工具链未安装 `rustfmt` 而无法执行。

### 升级说明

可从 1.8.0 直接升级。旧快照缺少当前用户存储字段时默认为 `0`，不需要数据库迁移。

## 1.8.0 — 存储空间趋势与完整服务器删除

- 修改时间：2026-08-05 16:20:05 +08:00
- 发布日期：2026-08-05
- 发布阶段：功能版本 / 内部预览
- 桌面平台：macOS、Windows
- 升级类型：兼容升级；自动增加远端清理队列表，不需要迁移历史数据。

### 版本概述

趋势页新增独占整行的存储空间栏目，每个挂载磁盘使用 `50 × 4`、共 200 格的华夫饼显示当前占用，并直接标注已用与总容量。删除服务器同时清理本地记录、本地历史、远端采集进程和服务器用户目录中的 `~/.racktop` 数据；远端不可达时会保留隐藏清理任务并自动重试最多 24 小时。

### 新增功能

- 实时采样服务器非临时文件系统的挂载点、已用容量、总容量和可用容量。
- 趋势页新增“存储空间”栏目；磁盘上下排列，不参与 CPU/GPU 的左右双列布局，每个磁盘固定使用 `50 × 4` 华夫饼并在下方显示 GB/TB 容量。

### 优化内容

- 删除确认明确说明会清理远端 RackTop 数据，服务器上的其他文件不受影响。
- 清理失败时通过系统通知说明等待重连状态；自动清理超过 24 小时后停止重试，并通知手动清理命令。

### 修复内容

- 修复删除服务器只清理本地 SQLite 和钥匙串、远端守护进程及隐藏历史文件继续保留的问题。

### 保持不变的行为

- 远端清理只针对当前用户的 `~/.racktop` 目录，不会删除服务器上的其他目录、进程或用户数据。
- 测试使用隔离的临时数据库和脚本断言，不连接或删除用户现有服务器。

### 验证记录

- 前端 Vitest：19 个测试文件、69 项测试全部通过。
- TypeScript 与 Vite 生产构建通过；Rust 单元测试 29 项、`cargo check` 通过。
- 本地开发页使用真实浏览器检查：存储区与父容器同宽，每块磁盘 50 列 × 4 行、各 200 格，单格保持正方形，GB/TB 文案在网格下方。
- 未执行真实服务器删除验证，避免误删用户现有服务器；远端删除流程通过固定脚本和隔离队列测试验证。
- `cargo fmt --check` 未执行成功：本机 stable 工具链未安装 `rustfmt`。
- 已从仓库最新 `dist` 构建 `RackTop.app`，Info.plist 版本为 `1.8.0`，并通过 `codesign --verify --deep --strict` 。

### 已知事项

- macOS 系统通知仍依赖用户授予 RackTop 通知权限。
- 存储华夫饼当前按挂载文件系统总使用量显示，不是逐 Unix 用户的磁盘占用分布；逐用户扫描需要额外权限和明确的数据源，且不应放入高频实时采集。

### 升级说明

可从 1.7.2 直接升级。SQLite 会自动增加远端清理队列表；服务器下一次实时采样后开始显示存储空间。

## 1.7.2 — 优化使用分布与空闲算力交互

- 修改时间：2026-08-05 15:03:00 +08:00
- 发布日期：2026-08-05
- 发布阶段：Bugfix / 内部预览
- 桌面平台：macOS、Windows
- 升级类型：兼容升级；不需要迁移配置或历史数据。

### 版本概述

本版本修正 GPU 使用分布华夫饼未充分利用卡片宽度的问题，并重新定义“寻找空闲算力”卡片的主要点击区域：可用 GPU 的卡片主体直接打开终端，不可用 GPU 的卡片主体直接进入预约，详情按钮保持为独立操作。服务器表单中的 SSH 快速配置折叠区也增加了明确的可展开提示，同时校正新增服务器默认历史策略并修复侧栏实时拖动排序。

### 优化内容

- GPU 使用时长和显存积分华夫饼改为 `25 × 4` 的紧凑网格；100 个正方形单元横向铺满卡片但不纵向拉伸，图例固定在网格下方，双列布局在窄窗口转为单列。
- 用户色块与卡片表面混合以降低饱和度，未使用区域继续保持中性灰色。
- 空闲算力卡片除右上角详情按钮外，整张卡片均作为主要操作区；可用卡显示终端语义并打开 GPU 快捷终端，不可用卡显示预约语义并打开单卡预约。
- 整卡操作和详情按钮使用两个独立、无嵌套的按钮命中层，保留键盘焦点、悬停和按压反馈，避免点击详情时误触发终端或预约。
- “SSH 密钥快速配置”收起状态增加说明文字、指针光标和右侧方向箭头；展开后箭头向下旋转，使折叠区的可点击性与当前状态更易识别。
- 侧栏服务器在拖动经过目标行上、下半区时立即预览插前或插后位置，相邻行以 180ms 可中断位移动画让位；松手后才持久化，拖出列表或保存失败会恢复原顺序，并尊重减少动态效果设置。

### 修复内容

- 新安装和新增服务器的本地历史默认保留期由 30 天校正为 90 天；远端持续保存 30 天每次新增均默认开启，不再继承上一次新增服务器关闭开关的选择。编辑已有服务器仍保留原配置。
- 修复侧栏排序只在放下时尝试插到目标前方、拖动过程没有位置反馈且无法稳定移到列表末尾的问题。
- 修复详情页 GPU 卡片五列统计区的功耗值在窄卡片中把数值与 `W` 拆成两行、破坏同排对齐的问题；MBW、温度、功耗、进程和 SM 的数值现在保持单行。
- 修复添加服务器时未填写用户名或主机地址仍能复制带占位符的 SSH 快速配置命令的问题；现在会阻止复制，在快速配置区显示克制但醒目的红色说明，并标出缺失字段。

### 验证记录

- `vitest run`：19 个测试文件、68 项通过，覆盖两组 `25 × 4` 华夫饼、低强调混色、快速配置折叠与复制前校验、新服务器默认值及服务器插前/插后排序。
- `tsc --noEmit`：通过。
- `cargo test --manifest-path src-tauri/Cargo.toml`：27 项通过，包含桌面端新安装 90 天本地历史默认值。
- `cargo check --manifest-path src-tauri/Cargo.toml`：通过。
- `sh -n`：macOS 打包脚本、远端采集器和守护脚本语法检查通过。
- Vite 生产构建：通过；因 iCloud 工作区文件 I/O 问题，在 `/tmp` 本地副本使用同一源码和依赖完成，保留单个 bundle 超过 500 kB 的既有提示。
- macOS Tauri Release App：`1.7.2` 构建通过，产物为 `src-tauri/target/release/bundle/macos/RackTop.app`；完整 App ad-hoc 重签后 `codesign --verify --deep --strict` 通过。
- 构建资源一致性：仓库与 `/tmp` 临时副本的源码一致；Tauri 代码生成目录中的最新 Brotli 嵌入 CSS 解压后确认包含功耗单行、快速配置红色校验、缺失字段错误态、侧栏拖动态和 `25` 列网格规则。
- 最终 App GUI 自动点击验证未完成：macOS 拒绝本轮辅助功能控制 RackTop；未将此项记为通过。

### 已知事项

### 升级说明

可从 1.7.1 直接升级。服务器配置、本地 SQLite、远端采集脚本和历史数据格式均保持兼容。

## 1.7.1 — 修复历史采集与进程信息布局

- 修改时间：2026-08-05 02:40:06 +08:00
- 发布日期：2026-08-05
- 发布阶段：Bugfix / 内部预览
- 桌面平台：macOS、Windows
- 升级类型：兼容升级；本地 SQLite 自动增加在线使用分布分钟索引，远端脚本会在下次连接时自动更新。

### 版本概述

本版本修正远端历史在部分 Linux 服务器上的连接失败，并重新划分 App 与远端守护进程的采集职责：RackTop 在线时由本机持续生成使用分布，远端只在 App 离线后接管。概览进程表同步改善 GPU、PID、用户、关系和长命令的可读性。

### 优化内容

- RackTop 在线时约每分钟把用户级 GPU 活跃时间、显存积分和 GPU 覆盖时间写入本机 SQLite；未开启远端保存也能正常形成使用分布。
- 已开启远端保存时，现有实时 SSH 采样会更新隐藏心跳；远端守护进程在心跳 90 秒内保持静默，App 退出或崩溃后自动恢复每分钟采集。
- 本地分钟桶优先于同一分钟的远端数据，避免 App 启动边界发生重复统计；本地使用分布最多保留 90 天。
- 概览与进程页将 GPU、PID、用户拆为独立列；关系字段将父资源、父 PID 和子进程语义分开展示，并为长命令保留弹性宽度。
- 进程展开详情改为稳定的事实字段区和整行命令区，使用“上箭头 + 收起”替代突兀的悬浮关闭按钮。
- 首次添加服务器改用独立前置弹窗说明 `Ed25519 + SSH Agent` 推荐方案和快速配置步骤；编辑已有服务器时不重复打断。
- 概览 GPU UTL/MEM 实时曲线使用 90% 不透明度，保留清晰度并降低重叠区域的遮挡。

### 修复内容

- 修复 `mawk 1.3.4` 对直接传给 `printf` 的三元表达式处理异常，导致远端 CPU、内存和 Swap 百分比为空、服务器保存后连接失败的问题。
- 修复旧版畸形远端记录导致整批同步中止的问题；无效行现在会被跳过，其他有效历史仍可导入。
- 修复 GPU 使用分布完全依赖“远端持续保存 30 天”、未开启时一直没有数据的问题。
- 修复空闲 GPU 没有进入覆盖分母、用户使用比例被放大的问题；空闲分钟现在只计覆盖，不会显示为用户。
- 修复历史趋势跨缺失时段仍连续连线或把缺失 GPU 指标回退为零的问题；缺口使用低强调灰色区并中断实线。
- 修复侧栏拖动排序偶发只在第一次生效、概览页出现不需要的模块拖动控件、终端未占满可用区域以及“趋势”页签位置不正确的问题。
- 修复 About 中作者主页和 GitHub 仓库链接无法离开 WebView 的问题；桌面端现在调用系统默认浏览器，失败时显示明确提示。
- 修复“第三方许可”展开后箭头仍指向右侧的问题；箭头现在随 `aria-expanded` 状态转为向下，正确表达收起/展开关系。

### 保持不变的行为

- 未开启远端持续保存时，App 离线期间不生成历史数据，也不会用零补齐缺失时段。
- 使用分布仍只持久化时间桶、GPU、Unix 用户、活跃秒数、显存积分和覆盖量，不保存 PID、命令、路径或终端输入输出。
- 系统用户以及常见监控、编辑器、Codex、Claude 和 VPN 服务不会计入用户使用分布。

## 1.5.0 — 远端历史持续采集与同步

- 修改时间：2026-08-04 12:08:28 +08:00
- 发布日期：2026-08-04
- 发布阶段：功能版本（本地开发验证）
- 桌面平台：macOS、Windows
- 升级类型：兼容更新；SQLite 自动增加远端历史配置、同步游标和快照唯一索引，不需要手动迁移

### 版本概述

RackTop 1.5.0 增加可选的远端历史持续采集。启用后，服务器在 RackTop 完全关闭期间仍会每分钟保存一次轻量 CPU/GPU 资源样本，并在本地 App 再次打开后增量同步到 SQLite，从而避免历史热力图因桌面端未运行而长时间断档。

### 新增功能

- 服务器编辑页的“采样与历史”区域增加“远端持续保存 30 天”开关；现有服务器默认关闭，只有用户明确启用并保存时才修改远端环境。
- 启用时通过 SSH 启动当前 Linux 用户自己的隐藏常驻采集进程，每分钟记录 CPU UTL、系统 MEM、Swap、各 GPU UTL 和 GPU MEM，并在服务器上滚动保留 30 天。
- 远端历史不记录 GPU/CPU 进程、PID、用户名、命令、密码、SSH 地址或认证信息。
- 远端脚本、PID、锁和历史均以点文件形式保存在当前用户的隐藏目录 `~/.racktop`，并使用仅当前用户可读写的权限创建。
- App 打开后先同步已启用服务器的现有数据，再自动检查并启动远端常驻进程；之后每 5 分钟执行一次低频增量补同步和存活检查。该流程与 0.5 秒实时状态刷新和本地曲线采样相互独立。
- 服务器连接页显示远端历史启用状态和最近同步时间，历史页说明当前数据来自本地和远端。
- 关闭开关时只停止 RackTop 自己的常驻进程，不删除服务器上已产生的隐藏历史文件。

### 优化内容

- SQLite 为 `(server_id, timestamp)` 增加唯一索引；本地实时样本和远端同步样本落在同一秒时不会产生重复记录。
- 每台服务器保存独立的远端同步游标，并回退 60 秒读取以容忍边界重试；导入使用事务处理，重复同步保持幂等。
- 同步会拒绝早于 31 天或超前本机 5 分钟以上的远端时间戳，避免服务器时钟错误破坏本地历史保留边界。
- 远端采集器只依赖 POSIX shell、`awk`、`/proc` 和可选的 `nvidia-smi`；常驻进程属于当前 SSH 用户，不部署远端数据库，也不需要 root 权限。
- 守护进程使用隐藏 PID 文件检查存活状态，App 重复打开或周期检查不会启动多个采集实例；支持 `setsid` 的服务器会将进程与 SSH 会话分离。

### 保持不变的行为

- 未开启远端历史的服务器继续只在 RackTop 运行时写入本机 SQLite。
- 本地历史保存期仍由每台服务器的 1/7/30/90 天设置控制；远端固定最多保存 30 天。
- 实时状态、进程采样、空闲预约和远程结束进程行为不受远端历史同步影响。

- 当前已符合条件的 GPU 在创建时保存为已知基线，不会立即重复通知；新的符合设备或退出后再次符合的设备才会触发。
- “当前快照”预约必须连续满足 30 秒；选择 5/10/30/60 分钟持续条件时沿用对应历史窗口判断。

- 预约持久化到本地 SQLite，应用重启后仍可恢复；完全退出应用期间不执行监测。
- 进程采样同时采集 GPU 与 CPU 任务，并记录 PID、父 PID、用户、命令、CPU、内存和运行时间；CPU 区块只保留 RSS 内存严格大于 1 GB 的 GPU 直接子进程，以及当前有 CPU 占用且占用最高的 12 个非系统用户进程组主进程。
- CPU 任务统一过滤常见后台服务，包括 nvitop/nvtop、VS Code/Cursor Remote、Codex、Claude、JetBrains Remote、用户桌面与音频会话，以及 Tailscale、ZeroTier、OpenVPN、WireGuard、Clash/Mihomo、sing-box、V2Ray/Xray、Cloudflare Tunnel 等常见 VPN/代理进程。

### 本版本优化与修复

- 修复数字筛选输入无法删除 `0` 的问题，清空后可直接输入新数值，例如 `20`，不会变成 `020`。
- 空闲 GPU 筛选默认使用当前快照即时返回；只有持续时间条件需要查询历史窗口。
- 修复筛选结果短暂出现后消失的问题，筛选条件在数据刷新期间保持有效。
- GPU 状态墙以显存占用作为卡片背景的主要状态语义，GPU 核心利用率仅作为辅助数值强调。
- 显存占用低于 `1%` 时按未使用处理并显示为 `0%`，使用中性背景，避免少量系统进程造成误判。
- 显存占用 `1%–49%` 使用蓝色提示，`50%–84%` 使用橙色提示，`85%–100%` 使用红色提示。
- 对采集到的百分比进行 `0%–100%` 边界限制，避免界面显示异常数值。

### 详情与连接能力

服务器详情包含概览、GPU、CPU、进程、历史、日志和连接页面。Host Key 未确认时不会自动接受；指纹发生变化时会阻止连接。密码不会写入命令行、日志或 SQLite，只保存在当前会话内存或系统凭据存储中。

当 Ubuntu/Debian 服务器缺少 NVIDIA 驱动时，RackTop 可以提供诊断和安装协助。应用不会自动执行 `sudo`，只有在用户连续确认后才会尝试通过免交互 `sudo -n` 安装。

### 已知限制

- 当前 macOS 安装包使用 ad-hoc 签名；公开分发前仍需 Apple Developer 签名与公证。
- Windows MSI/NSIS 构建与自动化 smoke test 已配置，但仍需在真实 Windows runner 上完成一次发布验证。
- 浏览器模式用于界面预览，展示的是本地演示数据；真实 SSH、系统凭据、托盘和通知能力仅在 Tauri 桌面应用中可用。
- 当前版本面向使用 NVIDIA GPU、可通过 OpenSSH 访问且提供 `nvidia-smi` 的 Linux 服务器。

### 升级说明

0.1.0 是首个版本，无需执行数据迁移。应用配置和历史数据保存在本机；删除服务器时，与该服务器关联的历史数据也会被删除。
