# RackTop 版本信息

本文档记录 RackTop 各版本的用户可见变化、验证范围和发布注意事项。最新版本始终位于最上方。

## 1.22.0 — 模型副本管理

- 修改时间：2026-08-19 03:55:54 +08:00
- 发布日期：2026-08-19
- 发布阶段：功能版本 / 内部预览
- 桌面平台：macOS、Windows
- 升级类型：兼容升级；既有项目、数据集、服务器和同步记录无需迁移。

### 版本概述

“我的项目”新增模型分类，用于在多台服务器之间统一管理模型权重和相关文件副本。模型复用项目与数据集的完整同步工作流，同时保持独立的业务语义。

### 新增功能

- “我的项目”新增“模型”标签页、数量和空状态。
- 添加同步对象时支持选择“模型”，并配置模型名称、主服务器、主目录、目标服务器和每台服务器的副本目录。
- 模型支持状态检查、批量同步、单目标同步、暂停/继续、编辑和移除配置。
- 本地网页预览新增 `Llama-3-8B` 模型样例，展示已同步与待创建副本。

### 保持不变的行为

- 只有“项目”提供启动任务入口；模型作为可复用资产不会被误当作运行项目。
- 只有“数据集”可以被项目关联；模型不会出现在关联数据集列表中。

### 验证记录

- ProjectView 与 ProjectForm 相关 19 项前端测试通过。
- TypeScript 检查与 Vite 生产构建通过；Vite 仍提示主 JavaScript 分块大于 500 kB。
- Rust 存储层 28 项测试通过，确认新模型类型兼容现有 SQLite 存储和同步记录。
- 在本地 WebView 预览中验证模型标签、模型样例卡、目标副本操作和模型添加表单。
- Tauri macOS Release App 构建成功，临时目录副本完成 ad-hoc 签名并通过深度严格验签。
- 原生 macOS App 中验证既有用户数据无需迁移，模型标签和专用空状态按预期显示。
- 未实际执行远程模型同步，避免在用户服务器上产生未确认的文件变更。

## 1.21.0 — 启动配置与命令接管

- 修改时间：2026-08-19 03:44:22 +08:00
- 发布日期：2026-08-19
- 发布阶段：功能版本 / 内部预览
- 桌面平台：macOS、Windows
- 升级类型：兼容升级；既有服务器、项目、启动配置和任务记录无需迁移。

### 版本概述

完善从已有 Shell 命令创建 RackTop 启动任务的工作流。RackTop 现在可以保留用户命令结构，按所选项目和 GPU 替换运行上下文，识别项目日志与训练超参数，并通过更紧凑的启动配置界面完成资源选择和启动前检查。

### 新增功能

- 支持从粘贴的多行 Shell 命令识别工作目录、`CUDA_VISIBLE_DEVICES`、实际训练命令和项目日志路径。
- 支持在选择项目或 GPU 后，仅替换命令中的工作目录和 GPU 编号，同时保留环境变量、Conda、训练参数及其他命令结构。
- 支持识别重定向、`tee`、日志参数及缺失重定向符的常见复制格式，并将项目日志路径同步到 RackTop 受管日志。
- 支持从 Python 训练命令解析有值参数和布尔参数，在可展开的“名称 / 值”列表中直接编辑。
- 启动配置改为以项目为主导的工作区；每个项目单独保存可复用命令和超参模板，空项目直接提供添加入口。
- 从配置进入运行时保留项目上下文，可针对本次任务切换服务器、对应项目副本目录、GPU 卡号和超参值。
- 启动配置弹窗新增独立“添加配置”操作，可在不启动任务的情况下保存模板。
- 资源筛选新增默认开启的“是否独占”，用于排除存在其他用户 GPU 工作负载的设备。

### 优化内容

- 启动配置页改为左侧项目导航与右侧配置工作区，配置摘要直接展示可编辑超参、目录切换方式、默认资源和最近运行。
- 超参数编辑器改为高密度两列表，普通值仅在聚焦时显示输入边界，布尔参数使用复选框。
- 运行位置的服务器摘要显示“GPU 数量 · 可用 / 总量 GB 系统 MEM”，GPU 摘要显示“可用 / 总量 GB MEM”。
- 资源筛选统一为 GPU 数量、每卡最低空闲显存和是否独占三列。
- 服务器、GPU 和启动配置的选中状态改为克制的中性边框与浅色背景，减少大面积强调色。
- 启动预览始终显示 RackTop 受管日志路径；识别到项目日志时同时显示同步目标。

### 修复内容

- 修复粘贴完整命令后回退到默认模板、导致原始环境变量和训练命令丢失的问题。
- 修复移除 `nohup` 和 `CUDA_VISIBLE_DEVICES` 时误删相邻 `env` 或实际执行命令的问题。
- 修复项目日志只识别单一 `> ... 2>&1 &` 形式，无法处理其他常见日志写法的问题。
- 修复 Conda 启动参数被误识别为训练超参数的问题。
- 修复启动配置与超参数区域行高过大、信息层级松散及资源筛选位于可视区域之外的问题。
- 修复“是否独占”字段缺少独立标题、控件高度高于相邻资源筛选项的问题。
- 修复启动弹窗右侧工作区过宽、超参数表和服务器卡片横向留白过多的问题。

### 保持不变的行为

- RackTop 仍使用 `~/.racktop/runs/<task-id>/output.log` 作为受管日志源；项目日志路径存在时由启动器建立同步关系，而不会把后台重定向重新塞回命令体。
- 未设置项目日志路径时继续使用 RackTop 默认日志，不额外写入项目目录。
- “是否独占”只排除其他用户的有效 GPU 工作负载，系统显示进程和持久化守护进程仍按现有规则忽略。

### 验证记录

- 启动命令解析与 ManagedProcessView 相关测试共 12 项通过。
- TypeScript 检查与 Vite 生产构建通过；Vite 仍提示主 JavaScript 分块大于 500 kB，不影响本版本功能。
- Tauri macOS Release App 构建成功；临时目录中的本地预览副本完成 ad-hoc 签名并通过深度严格验签。
- 在包含 6 台在线服务器、18 张 GPU 和真实项目配置的 macOS App 中完成视觉验收，确认项目导航、配置摘要、单一分隔线、默认独占筛选和超参数展开编辑均按预期显示。
- 在本地 WebView 实时预览中验证服务器与 GPU 摘要均显示可用/总量内存，且在现有卡片宽度内无溢出。
- 原生 App 中已验证“调整并运行”保留项目上下文，并在预览中按所选服务器和 GPU 替换项目目录与 `CUDA_VISIBLE_DEVICES`；未实际启动远程任务。
- 未实际提交远端训练任务，避免在用户服务器上创建未经确认的计算进程。

### 已知事项

- Vite 主 JavaScript 分块仍大于 500 kB，后续可按页面拆分以优化首次加载体积。
- iCloud 工作区内的 App 副本带有扩展属性，无法直接完成 ad-hoc 签名；本次使用 `/private/tmp` 中的等价构建副本完成签名和原生验收。

### 升级说明

可从 1.20.0 直接升级。既有启动配置保持兼容；首次编辑或保存后可使用新增的项目日志路径和超参数编辑能力。

## 1.20.0 — 未关联进程任务化

- 修改时间：2026-08-13 12:37:35 +08:00
- 发布日期：2026-08-13
- 发布阶段：功能版本 / 内部预览
- 桌面平台：macOS、Windows
- 升级类型：兼容升级；不改变服务器、项目、历史数据或已有任务记录的存储格式。

### 版本概述

统一 RackTop 管理任务与外部启动进程的展示结构，让未关联进程也能按任务语义查看资源、子进程和可用操作；同时将项目、空闲算力与任务启动收敛为可预填的连续工作流。

### 新增功能

- 未关联进程按服务器和根 PID 聚合，并在任务卡展开区中显示子进程。
- 未关联进程支持关联项目，关联后直接进入 RackTop 任务视图。
- 支持将外部进程的命令保存为启动配置。
- 未关联进程提供关联项目、保存配置、打开终端和结束进程四类操作。
- 支持从项目卡片和可用 GPU 直接进入任务启动，并自动预填项目、服务器或 GPU。
- “我的项目”新增项目和数据集标签页，并按最近执行、最近添加的顺序展示。

### 优化内容

- 统一关联与未关联进程的卡片层级，未知工作目录和日志明确显示为“未获取”。
- 关联项目后，运行位置只显示项目源服务器或已配置副本的在线服务器。
- 取消同一服务器内无意义的 GPU 型号筛选，只保留 GPU 数量和每卡最低空闲显存。
- 启动命令预览补充工作目录、后台运行、日志重定向和 GPU 环境变量语义。
- 空闲 GPU 的卡片操作区区分可用与不可用状态；可用卡可直接启动任务、打开终端或查看详情。
- “我的进程”在没有运行任务时仅保留居中的启动入口；存在任务时将入口收敛到右上角。

### 修复内容

- 修复只有未关联进程时，页面上方仍保留大块空任务状态的问题。
- 修复 GPU 选择卡的型号与显存文本越界覆盖相邻卡片的问题。
- 修复任务启动入口图标和位置不一致造成的操作语义混淆。

### 保持不变的行为

- RackTop 启动的任务仍提供任务日志和重启；未关联进程不伪造这两项能力。
- 远端任务仍通过独立运行目录、`nohup` 和可用时的 `setsid` 脱离 RackTop 运行。

### 验证记录

- ManagedProcessView、ProjectView 及其交互测试共 13 项通过。
- TypeScript 检查与 Vite 生产构建通过；Vite 仍提示主 JavaScript 分块大于 500 kB，不影响本版本功能。
- macOS Release `RackTop.app` 构建成功，并通过 `codesign --verify --deep --strict`。

### 已知事项

- 未在真实服务器上执行关联、保存配置或结束外部进程操作，避免更改用户正在运行的任务。
- 当前工作区的 `node_modules` 已损坏；最终测试与 macOS 打包在隔离构建副本中完成。

### 升级说明

可从 1.19.0 直接升级，无需迁移服务器、项目、启动配置或任务记录。

## 1.19.0 — 我的进程任务管理

- 修改时间：2026-08-11 18:53:30 +08:00
- 发布日期：2026-08-11
- 发布阶段：功能版本 / 内部预览
- 桌面平台：macOS、Windows
- 升级类型：兼容升级；不改变服务器、项目、历史数据或现有进程的数据格式。

### 版本概述

将“我的进程”扩展为跨服务器任务入口，在保留原有进程查看能力的同时，支持基于项目、服务器和 GPU 启动并持续管理任务。

### 新增功能

- 新增运行中、启动配置和最近结束三个任务视图。
- 支持选择项目、目标服务器、GPU 数量、型号和最低空闲显存后启动远端任务。
- 支持保存启动配置，并从历史任务快速重新运行。
- 支持查看 RackTop 管理任务的实时日志、工作目录、根 PID、进程关系和 GPU 指标。
- 支持二次确认后结束任务根进程及其子进程。
- 远端任务使用独立运行目录和脱离终端的进程组，关闭 RackTop 后任务仍可继续运行。
- 保留由终端或其他工具启动的当前用户进程，并统一显示为未关联进程。

### 优化内容

- “启动任务”固定在“我的进程”的页面工具栏，不进入共享顶部栏。
- 继续使用原有的侧栏用户图标，保持既有导航识别习惯。
- 按 Apple 设计原则提高页面、任务列表和启动弹窗的字体可读性，同时保持监控界面的紧凑密度。
- 远端状态轮询只在状态实际变化时更新，避免重复 SSH 请求和界面抖动。
- 任务进程归属增加当前用户与目标 GPU 约束，避免将其他用户或其他 GPU 上的同名命令错误关联。
- 单文件项目自动使用父目录作为工作目录，并为 Python 文件生成对应的默认启动命令。

### 保持不变的行为

- 除“我的进程”页面外，其他页面的布局、样式和交互保持不变。
- 现有服务器采集、项目同步、历史趋势和通知规则保持不变。
- 密码、Token 和其他秘密不会写入启动配置或任务记录。

### 验证记录

- TypeScript 检查与 Vite 生产构建通过；Vite 仍提示主 JavaScript 分块大于 500 kB，不影响本版本功能。
- 新增的“我的进程”页面边界、项目工作目录和进程归属测试共 5 项通过。
- 前端全量测试已完成的 30 个文件全部通过；3 个既有 jsdom 交互测试在 iCloud 工作区加载时长时间无输出，已终止并记录为未完成。
- Rust 全量测试 65 项通过、0 项失败；另有 2 项依赖外部 SSH 测试服务器的集成测试按预期忽略。
- Rust `cargo check` 在隔离构建目录通过；仓库整体 `cargo fmt --check` 因大量既有 Rust 文件未采用 rustfmt 格式而未作为本版本阻塞项。
- Tauri Release 编译与 macOS App-only 打包通过，短版本号和构建号均为 `1.19.0`。
- 最终 macOS App 完成临时签名，压缩包解包后通过深度严格验签。
- 在包含 6 台在线服务器、18 张 GPU 和 2 个项目的 macOS 实机数据中验证页面入口、原侧栏图标、页面内启动按钮、启动弹窗、项目路径和默认命令。

### 已知事项

- 本次未实际提交远端启动任务，避免在用户服务器上创建未经确认的计算进程；远端启动、日志和结束操作仍需在明确选择任务后进行最终验收。

### 升级说明

可从 1.18.5 直接升级，既有服务器、项目、数据集、历史记录和设置保持兼容；启动配置和任务记录会在首次使用“我的进程”新功能后保存在本机。

## 1.18.5 — 我的项目状态与操作收敛

### 修复内容

- 修复单个同名候选目录被界面算作缺失副本、但实际无法加入补齐计划的问题。
- 修复普通“保存”仍向提交回调传递启用同步计划的含混契约。

## 1.18.4 — 关联数据集同步交互修复

- 修改时间：2026-08-11 12:06:20 +08:00
- 发布日期：2026-08-11
- 发布阶段：Bugfix / 内部预览
- 桌面平台：macOS、Windows
- 升级类型：兼容升级；不改变项目、数据集或同步记录的数据格式。

### 版本概述

简化编辑项目时补齐关联数据集的工作流，使缺失副本可以与项目同步一次完成，同时保留“保存”只更新配置的明确语义。

### 优化内容

- 编辑项目时可勾选缺失的关联数据集副本，并通过底部“保存并同步”一次性补齐。
- 数据集补齐计划直接显示缺失服务器数量，重新检测后会自动丢弃已经失效的计划。

### 修复内容

- 关联数据集补齐只包含当前确实缺失的服务器；已存在、连接失败或同名冲突的目标不会重复传输。
- 普通“保存”只保存项目配置，即使已经勾选补齐计划也不会传输文件。

### 验证记录

- 前端 Vitest 31 个文件、141 项测试全部通过，包含编辑态数据集补齐、仅同步缺失副本及普通保存不传输的回归测试。

## 1.5.0 — 远端历史持续采集与同步

- 修改时间：2026-08-04 12:08:28 +08:00

### 版本概述

RackTop 1.5.0 增加可选的远端历史持续采集。启用后，服务器在 RackTop 完全关闭期间仍会每分钟保存一次轻量 CPU/GPU 资源样本，并在本地 App 再次打开后增量同步到 SQLite，从而避免历史热力图因桌面端未运行而长时间断档。

### 新增功能

- 服务器编辑页的“采样与历史”区域增加“远端持续保存 30 天”开关；现有服务器默认关闭，只有用户明确启用并保存时才修改远端环境。
- 启用时通过 SSH 启动当前 Linux 用户自己的隐藏常驻采集进程，每分钟记录 CPU UTL、系统 MEM、Swap、各 GPU UTL 和 GPU MEM，并在服务器上滚动保留 30 天。
- 远端历史不记录 GPU/CPU 进程、PID、用户名、命令、密码、SSH 地址或认证信息。
- 远端脚本、PID、锁和历史均以点文件形式保存在当前用户的隐藏目录 `~/.racktop`，并使用仅当前用户可读写的权限创建。
- App 打开后先同步已启用服务器的现有数据，再自动检查并启动远端常驻进程；之后每 5 分钟执行一次低频增量补同步和存活检查。该流程与 0.5 秒实时状态刷新和本地曲线采样相互独立。
- 服务器连接页显示远端历史启用状态和最近同步时间，历史页说明当前数据来自本地和远端。
- 关闭开关时只停止 RackTop 自己的常驻进程，不删除服务器上已产生的隐藏历史文件。

### 优化内容

- SQLite 为 `(server_id, timestamp)` 增加唯一索引；本地实时样本和远端同步样本落在同一秒时不会产生重复记录。
- 每台服务器保存独立的远端同步游标，并回退 60 秒读取以容忍边界重试；导入使用事务处理，重复同步保持幂等。

- 远端采集器只依赖 POSIX shell、`awk`、`/proc` 和可选的 `nvidia-smi`；常驻进程属于当前 SSH 用户，不部署远端数据库，也不需要 root 权限。
- 守护进程使用隐藏 PID 文件检查存活状态，App 重复打开或周期检查不会启动多个采集实例；支持 `setsid` 的服务器会将进程与 SSH 会话分离。

### 保持不变的行为

- 未开启远端历史的服务器继续只在 RackTop 运行时写入本机 SQLite。
- 本地历史保存期仍由每台服务器的 1/7/30/90 天设置控制；远端固定最多保存 30 天。

- 进程采样同时采集 GPU 与 CPU 任务，并记录 PID、父 PID、用户、命令、CPU、内存和运行时间；CPU 区块只保留 RSS 内存严格大于 1 GB 的 GPU 直接子进程，以及当前有 CPU 占用且占用最高的 12 个非系统用户进程组主进程。

- 顶部固定标题栏改为清晰的不透明背景和浅色分隔线，移除毛玻璃与下沿渐隐，避免产生页面尚未滑到顶部的错觉。

## 0.1.0 — 首个 MVP 版本

- 发布日期：2026-08-03
- 发布阶段：MVP / 内部预览
- 桌面平台：macOS、Windows
- 技术栈：Tauri 2、React、TypeScript、Rust、SQLite

### 版本概述

RackTop 0.1.0 提供无需在远程服务器安装 Agent 的多服务器 GPU 监控体验。应用通过本机 OpenSSH 并发连接 Linux 服务器，在一个桌面界面中查看 GPU、CPU、系统负载、进程和历史趋势，并帮助用户快速找到空闲 GPU。

### 核心功能

- 添加、编辑、删除和搜索服务器，支持从 OpenSSH Config 导入配置。
- 支持 SSH Agent、私钥、密码、`~/.ssh/config`、ProxyJump 和 Host Key 指纹核验。
- 并发采集多台服务器，提供手动刷新、自动刷新、后台降频、失败重试和离线状态判断。
- 查看 GPU 利用率、显存、温度、功耗，以及 CPU、内存、Swap 和 Load。
- 查看 GPU 进程的用户、PID、命令、显存、CPU 占用和运行时长，并突出当前 SSH 用户。
- 将所有服务器组织为 GPU 状态墙：一台服务器一个瀑布流区块，仅展示 GPU 与 CPU 摘要，点击区块进入服务器详情。
- GPU 状态墙支持按名称、状态、GPU 数量、利用率或空闲数量排序，并记住用户的排序设置。
- 空闲 GPU 页面支持按利用率、可用显存、持续时间、GPU 型号和服务器标签筛选。
- 使用 SQLite 保存历史数据，支持趋势图、自定义采样间隔、趋势窗口和历史保留期。
- 支持系统托盘和桌面通知，可提示服务器离线、GPU 高温、GPU 空闲、显存释放、持续满载和任务退出。
- 支持跟随系统的浅色/深色主题、减少动效和当前用户强调色。
- 浏览器开发模式内置双服务器演示数据，便于不连接真实服务器时进行本地界面验证。

### 本版本优化与修复

- 修复数字筛选输入无法删除 `0` 的问题，清空后可直接输入新数值，例如 `20`，不会变成 `020`。
- 空闲 GPU 筛选默认使用当前快照即时返回；只有持续时间条件需要查询历史窗口。
- 修复筛选结果短暂出现后消失的问题，筛选条件在数据刷新期间保持有效。
- GPU 状态墙以显存占用作为卡片背景的主要状态语义，GPU 核心利用率仅作为辅助数值强调。
- 显存占用低于 `1%` 时按未使用处理并显示为 `0%`，使用中性背景，避免少量系统进程造成误判。
- 显存占用 `1%–49%` 使用蓝色提示，`50%–84%` 使用橙色提示，`85%–100%` 使用红色提示。
- 对采集到的百分比进行 `0%–100%` 边界限制，避免界面显示异常数值。

### 详情与连接能力

服务器详情包含概览、GPU、CPU、进程、历史、日志和连接页面。Host Key 未确认时不会自动接受；指纹发生变化时会阻止连接。密码不会写入命令行、日志或 SQLite，只保存在当前会话内存或系统凭据存储中。

当 Ubuntu/Debian 服务器缺少 NVIDIA 驱动时，RackTop 可以提供诊断和安装协助。应用不会自动执行 `sudo`，只有在用户连续确认后才会尝试通过免交互 `sudo -n` 安装。
