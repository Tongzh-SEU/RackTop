# RackTop 版本信息

本文档记录 RackTop 各版本的用户可见变化、验证范围和发布注意事项。最新版本始终位于最上方。

## 1.0.0 — RackTop 正式版本

- 修改时间：2026-08-03 18:13:26 +08:00
- 发布日期：2026-08-03
- 发布阶段：正式发布
- 桌面平台：macOS、Windows
- 升级类型：用户明确指定的首个正式主版本；兼容现有配置与数据，不需要迁移

### 版本概述

RackTop 1.0.0 是当前正式版本。它在完整的多服务器 GPU 监控、资源总览与空闲 GPU 发现能力之上，修复实时趋势图 X 轴时间标签过密的问题，并将 GPU 卡片中当前用户的显存强调改为容量光标，直接显示“你”占用的 GB 数，不再使用容易误解为总占用的整段色块。

### 本版本修改

- CPU UTL、GPU MEM、系统 MEM / SWP 和 GPU UTL 趋势图的 X 轴统一按 5 分钟间隔显示时间刻度。
- 仅修改坐标轴标签密度；数据采样、曲线数据点、图表更新方式、手动刷新 `180ms` 动画和后台静默更新行为均保持不变。
- GPU MEM 进度条在存在当前 SSH 用户进程时，在对应占比位置显示细光标和“你 X.X GB”标签；无当前用户占用时不渲染光标。
- 光标标签使用独立的垂直标签带，并将水平位置限制在进度条内，避免与右侧“已用 / 总量 GB”文案或卡片边界碰撞。

### 验证记录

- 前端单元测试 11 项通过，包含 5 分钟边界标签、非边界隐藏、0 占用不显示光标及当前用户容量光标定位测试；Rust 单元测试 11 项通过。
- TypeScript 检查、Vite 生产构建与 macOS 1.0.0 Release 应用构建通过；最终 `RackTop.app` 为 13 MB，应用短版本号与构建版本号均为 `1.0.0`。
- 本地浏览器四张趋势图实测标签为 `17:40、17:45、17:50、17:55、18:00、18:05`，相邻时间差为 5 分钟；图表动画字段与 0.2.0 保持一致。
- 在 `tongzh@10.201.129.199` 的 GPU 0 上通过 CUDA Runtime 临时分配 10 GiB，`nvidia-smi` 实测进程占用 `10738 MiB`；RackTop 正确识别当前用户、在约 44% 位置显示“你 10.5 GB”光标，并与右侧 `10.5 / 24 GB` 文案保持分离；同服务器 GPU 1 无当前用户进程，正确不显示光标。

### 已知事项

- Windows 安装包仍需在真实 Windows runner 上构建验证。

### 升级说明

可直接从 0.2.0 升级到 1.0.0；服务器配置、SSH 认证与 SQLite 历史数据均不变。

## 0.2.0 — GPU 总览与详情信息架构升级

- 修改时间：2026-08-03 17:43:50 +08:00
- 发布日期：2026-08-03
- 发布阶段：功能版本 / 内部预览
- 桌面平台：macOS、Windows
- 升级类型：兼容更新；SQLite 历史表会自动增加 GPU 显存与 Swap 利用率字段，无需手动迁移

### 版本概述

RackTop 0.2.0 将默认“总览”升级为全部服务器的 GPU 状态墙，并按实际监控优先级重构服务器概览、GPU 详情与趋势图。本版本同时修复 macOS WebKit 瀑布流、排序重排、Dock 图标、窗口收缩、系统资源卡片及手动刷新反馈等问题，使多服务器监控在浏览器和 macOS 应用中的布局与交互保持一致。

### 新增功能

- 默认“总览”现在一次展示全部服务器的 GPU 与 CPU 摘要；移除重复的“GPU 总览”导航入口，服务器详情仍可从状态墙或服务器列表进入。
- 服务器概览按“核心数据、GPU 状态、CPU 状态、实时趋势、当前进程”组织，趋势图按 CPU UTL、GPU MEM、系统 MEM / SWP、GPU UTL 的阅读顺序排列。
- 历史样本新增逐 GPU 的显存利用率与 Swap 利用率数据；旧 SQLite 数据库启动时自动增加 `gpu_memory_json`、`swap_utilization` 字段并保留已有记录。
- SSH 快照新增真实 CPU 型号采集，为空闲 GPU 页面提供跨服务器 CPU 型号筛选。

### 优化内容

- GPU 信息层级调整为 MEM 优先、UTL 次之，并在卡片底部集中显示 MBW、功耗、温度和进程数量。
- GPU 状态卡片采用用户选定的“极淡底色”方案：蓝、橙、红状态统一使用 `10%` 彩色边框权重和 `0.8%` 背景混合，醒目的颜色只保留给具体数值和进度条。
- GPU 状态墙的设备行改为“设备、显存、GPU”阅读顺序；背景填充长度直接对应显存占用比例，低于 `1%` 保持中性，UTL 仅使用独立数字强调色且后台刷新不播放填充动画。
- 概览中的 CPU 状态改为与 GPU 同尺寸的小卡片，统一放入资源状态网格；按系统 MEM、CPU UTL、1/5/15 分钟负载与 Swap 的顺序展示，点击可进入 CPU 详情。
- GPU 详情在常规宽度下自动采用紧凑多列布局，窗口缩小时回退为单列；选择设备不会再改变卡片顺序或引发布局跳动。
- 总览瀑布流改用可测量的 CSS Grid，并明确左右列的排序阅读顺序；切换“GPU 数量”等排序后不会在 macOS 上退化为纵向堆叠。
- 全局资源摘要在中等窗口宽度下会将排序控件换行，避免“平均 GPU”等数值被压缩成省略号。
- 手动“刷新全部”与单服务器重连使用独立反馈状态，后台自动采样不再让刷新按钮持续旋转。
- 顶部固定标题栏改为清晰的不透明背景和浅色分隔线，移除毛玻璃与下沿渐隐，避免产生页面尚未滑到顶部的错觉。
- 实时趋势图在后台采样时静默更新，不再每 2 秒上下展开；仅用户手动刷新时保留 `180ms` 的短反馈动画。
- GPU MEM、系统 MEM 与 SWP 的悬浮提示同时显示利用率和已用/总量 GB；图表更新时完整替换数据序列，避免不同图表之间残留旧 GPU 图例。
- macOS 标题栏保留交通灯安全区；Dock 使用无透明外缘的 macOS 专用图标源，避免系统为传统透明图标添加白色底板。
- 筛选数字输入允许清空后重新输入，`0` 可删除，输入 `20` 不会形成 `020`；当前快照筛选即时返回，持续时间筛选才查询完整历史窗口。
- 空闲 GPU 结果同时展示“可用”和“不可用”两种状态：可用设备优先、不可用设备随后按可用显存排序，并以中性灰卡片弱化但保留完整数据和详情入口。
- 空闲条件按 GPU MEM、CPU MEM、进程占用、GPU 型号、CPU 型号、持续时间、服务器标签排列；移除 GPU UTL 条件，进程占用只保留“不限”和“无人占用”，默认选择“无人占用”。
- 其他用户训练占用会忽略 `gdm`、显示服务、桌面合成器与 NVIDIA 常驻服务；其余进程合计不超过 GPU MEM `3%` 时也按未占用处理。

### 修复内容

- 修复日志、连接和 CPU“系统资源”模块标题或底部内容贴边、裁切及长文本溢出问题。
- 修复 GPU 状态墙相邻设备颜色无间距、显存状态色语义反转以及低于 `1%` 的系统占用误判；低于 `1%` 仍按未使用并显示中性背景。
- 修复百分比异常值与平滑曲线过冲造成 GPU 利用率超过 `100%` 的显示问题。
- 修复窄窗口下趋势图画布撑宽详情页、GPU 卡片横向裁切的问题。
- 修复空闲 GPU 使用未展示的进程条件否决结果；现在可用性只依据界面明确显示的 GPU/CPU MEM、可选其他用户占用与持续时间条件。
- 修复删除服务器后快照缓存残留、本地历史读取失败误判 SSH 离线、系统内存总量为 `0` 时显示 `NaN%`、当前用户进程选中态被覆盖及较旧刷新时间文案异常等逻辑问题。

### 保持不变的行为

- GPU 状态背景仍以显存占用为主语义，GPU 核心利用率只作为独立辅助指标。
- 空闲 GPU 页面保留固定的资源筛选条件，不增加自定义排序选项。
- 服务器配置、SSH 认证方式与已有历史记录保持兼容；数据库结构升级由应用自动完成。

## 0.1.1 — 稳定性与界面修复

### 版本概述

RackTop 0.1.1 是一次以问题修复为主的维护版本。本版本集中处理首个 MVP 在实际双服务器监控和 macOS 应用使用中发现的显示异常、数据边界与交互细节，使 GPU 状态墙、趋势图、日志和 SSH 连接页面更清晰、稳定。

### 修复内容

- 修复 GPU 趋势曲线在满载时可能视觉上超过 `100%` 的问题。采集结果、历史样本和图表数据现在都会限制在 `0%–100%`，折线不再因平滑插值发生过冲。
- 修复 GPU 状态墙中相邻 GPU 状态背景连在一起的问题，设备行之间现在保留清晰间距。
- 修复详情页“日志”模块标题贴边、时间与消息对齐不稳，以及较长错误信息可能溢出的问题。
- 修复详情页“连接”模块标题和内容排版不一致的问题；较长的私钥路径、SSH 地址与 ProxyJump 配置现在可以安全换行。
- 优化 macOS 窗口标题栏安全区，RackTop 品牌区不再紧贴窗口交通灯按钮；该间距只在桌面应用生效，不影响浏览器预览。
- 修复 GPU、CPU 或显存遥测出现无效值、负数或异常超限值时，进度条和汇总信息可能显示错误的问题。
- 修复系统内存总量暂时为 `0` 时，CPU 详情可能显示 `NaN%` 的问题。
- 修复当前用户进程被选中后，个人占用底色覆盖选中态的问题。
- 修复删除服务器后快照缓存未同步清理，导致 GPU 总数、空闲数量或最近刷新时间仍包含已删除服务器的问题；删除期间完成的旧采集也不会重新写回缓存。
- 修复本地历史读取失败时被误判为 SSH 采集失败、进而错误降低服务器在线状态的问题。
- 优化最近刷新时间的展示，较早的记录会按小时或天显示，不再出现数千分钟的文案。

### 保持不变的行为

## 0.1.0 — 首个 MVP 版本

- 发布日期：2026-08-03
- 发布阶段：MVP / 内部预览
- 桌面平台：macOS、Windows
- 技术栈：Tauri 2、React、TypeScript、Rust、SQLite

### 版本概述

RackTop 0.1.0 提供无需在远程服务器安装 Agent 的多服务器 GPU 监控体验。应用通过本机 OpenSSH 并发连接 Linux 服务器，在一个桌面界面中查看 GPU、CPU、系统负载、进程和历史趋势，并帮助用户快速找到空闲 GPU。

### 核心功能

- 添加、编辑、删除和搜索服务器，支持从 OpenSSH Config 导入配置。
- 支持 SSH Agent、私钥、密码、`~/.ssh/config`、ProxyJump 和 Host Key 指纹核验。
- 并发采集多台服务器，提供手动刷新、自动刷新、后台降频、失败重试和离线状态判断。
- 查看 GPU 利用率、显存、温度、功耗，以及 CPU、内存、Swap 和 Load。
- 查看 GPU 进程的用户、PID、命令、显存、CPU 占用和运行时长，并突出当前 SSH 用户。
- 将所有服务器组织为 GPU 状态墙：一台服务器一个瀑布流区块，仅展示 GPU 与 CPU 摘要，点击区块进入服务器详情。
- GPU 状态墙支持按名称、状态、GPU 数量、利用率或空闲数量排序，并记住用户的排序设置。
- 空闲 GPU 页面支持按利用率、可用显存、持续时间、GPU 型号和服务器标签筛选。
- 使用 SQLite 保存历史数据，支持趋势图、自定义采样间隔、趋势窗口和历史保留期。
- 支持系统托盘和桌面通知，可提示服务器离线、GPU 高温、GPU 空闲、显存释放、持续满载和任务退出。
- 支持跟随系统的浅色/深色主题、减少动效和当前用户强调色。
- 浏览器开发模式内置双服务器演示数据，便于不连接真实服务器时进行本地界面验证。

### 本版本优化与修复

- 修复数字筛选输入无法删除 `0` 的问题，清空后可直接输入新数值，例如 `20`，不会变成 `020`。
- 空闲 GPU 筛选默认使用当前快照即时返回；只有持续时间条件需要查询历史窗口。
- 修复筛选结果短暂出现后消失的问题，筛选条件在数据刷新期间保持有效。
- GPU 状态墙以显存占用作为卡片背景的主要状态语义，GPU 核心利用率仅作为辅助数值强调。
- 显存占用低于 `1%` 时按未使用处理并显示为 `0%`，使用中性背景，避免少量系统进程造成误判。
- 显存占用 `1%–49%` 使用蓝色提示，`50%–84%` 使用橙色提示，`85%–100%` 使用红色提示。
- 对采集到的百分比进行 `0%–100%` 边界限制，避免界面显示异常数值。

### 详情与连接能力

服务器详情包含概览、GPU、CPU、进程、历史、日志和连接页面。Host Key 未确认时不会自动接受；指纹发生变化时会阻止连接。密码不会写入命令行、日志或 SQLite，只保存在当前会话内存或系统凭据存储中。

当 Ubuntu/Debian 服务器缺少 NVIDIA 驱动时，RackTop 可以提供诊断和安装协助。应用不会自动执行 `sudo`，只有在用户连续确认后才会尝试通过免交互 `sudo -n` 安装。

- 前端单元测试：4 项通过。
- Rust 单元测试：9 项通过。
