# RackTop 版本信息

本文档记录 RackTop 各版本的用户可见变化、验证范围和发布注意事项。最新版本始终位于最上方。

## 1.6.0 — 增加远端历史同步状态

- 修改时间：2026-08-04 13:48:03 +08:00
- 发布日期：2026-08-04
- 发布阶段：功能版本
- 桌面平台：macOS、Windows
- 升级类型：兼容更新；不需要迁移配置或历史数据

### 版本概述

RackTop 1.6.0 为远端历史增加低干扰的同步反馈。当 App 离线较久后重新打开，用户可以看到多台服务器的同步进度、导入数量和失败状态，同时仍可继续使用已有本地数据。

### 新增功能

- 已启用远端历史的服务器距上次数据同步超过 10 分钟时，App 启动后立即在顶栏显示同步状态。
- 未超过 10 分钟的启动同步先静默执行；只有耗时超过 800ms 才显示反馈，避免快速同步导致界面闪烁。
- 同步中显示“已完成/总服务器数”；成功后显示本次新增历史记录数，2 秒后自动隐藏。
- 同步失败状态会保留，标明失败服务器数和 5 分钟重试节奏；点击可定位到首台失败服务器。

### 优化内容

- 顶栏为同步状态保留稳定宽度，状态变化不会挤动刷新按钮和通知入口。
- 五分钟例行后台同步在成功时保持静默，只保留需要用户注意的失败状态。
- 同步反馈不使用弹窗或全屏加载，不阻断实时监控、服务器切换或历史查看。

### 保持不变的行为

- 远端历史仍先增量同步，再检查并必要时重启远端守护进程。
- 远端采集周期、30 天保留上限、SQLite 去重和五分钟后台检查周期保持不变。

### 验证记录

- 前端单元与组件测试 `45/45` 通过，覆盖 10 分钟边界及进度、成功、失败文案。
- TypeScript 检查和 Vite 生产构建通过；构建保留既有的 500 kB chunk 体积提示。
- Rust 测试 `20/20` 通过；本次未修改 Rust 行为。
- macOS Tauri Release App 构建通过，应用版本为 `1.6.0`；ad-hoc 签名严格校验通过。
- Playwright CLI 可用，但本次本地浏览器会话未返回快照且未生成新图像，因此不记为视觉验证通过。

### 已知事项

- 当前未发现新增功能问题；本地 Playwright 快照会话异常仍需后续排查。

### 升级说明

可从 1.5.1 直接升级；服务器配置、远端守护进程、SQLite 数据库和历史样本均保持兼容。

## 1.5.0 — 远端历史持续采集与同步

- 修改时间：2026-08-04 12:08:28 +08:00
- 发布日期：2026-08-04
- 发布阶段：功能版本（本地开发验证）
- 桌面平台：macOS、Windows
- 升级类型：兼容更新；SQLite 自动增加远端历史配置、同步游标和快照唯一索引，不需要手动迁移

### 版本概述

RackTop 1.5.0 增加可选的远端历史持续采集。启用后，服务器在 RackTop 完全关闭期间仍会每分钟保存一次轻量 CPU/GPU 资源样本，并在本地 App 再次打开后增量同步到 SQLite，从而避免历史热力图因桌面端未运行而长时间断档。

### 新增功能

- 服务器编辑页的“采样与历史”区域增加“远端持续保存 30 天”开关；现有服务器默认关闭，只有用户明确启用并保存时才修改远端环境。
- 启用时通过 SSH 启动当前 Linux 用户自己的隐藏常驻采集进程，每分钟记录 CPU UTL、系统 MEM、Swap、各 GPU UTL 和 GPU MEM，并在服务器上滚动保留 30 天。
- 远端历史不记录 GPU/CPU 进程、PID、用户名、命令、密码、SSH 地址或认证信息。
- 远端脚本、PID、锁和历史均以点文件形式保存在当前用户的隐藏目录 `~/.racktop`，并使用仅当前用户可读写的权限创建。
- App 打开后先同步已启用服务器的现有数据，再自动检查并启动远端常驻进程；之后每 5 分钟执行一次低频增量补同步和存活检查。该流程与 0.5 秒实时状态刷新和本地曲线采样相互独立。
- 服务器连接页显示远端历史启用状态和最近同步时间，历史页说明当前数据来自本地和远端。
- 关闭开关时只停止 RackTop 自己的常驻进程，不删除服务器上已产生的隐藏历史文件。

### 优化内容

- SQLite 为 `(server_id, timestamp)` 增加唯一索引；本地实时样本和远端同步样本落在同一秒时不会产生重复记录。
- 每台服务器保存独立的远端同步游标，并回退 60 秒读取以容忍边界重试；导入使用事务处理，重复同步保持幂等。
- 同步会拒绝早于 31 天或超前本机 5 分钟以上的远端时间戳，避免服务器时钟错误破坏本地历史保留边界。
- 远端采集器只依赖 POSIX shell、`awk`、`/proc` 和可选的 `nvidia-smi`；常驻进程属于当前 SSH 用户，不部署远端数据库，也不需要 root 权限。
- 守护进程使用隐藏 PID 文件检查存活状态，App 重复打开或周期检查不会启动多个采集实例；支持 `setsid` 的服务器会将进程与 SSH 会话分离。

### 保持不变的行为

- 未开启远端历史的服务器继续只在 RackTop 运行时写入本机 SQLite。
- 本地历史保存期仍由每台服务器的 1/7/30/90 天设置控制；远端固定最多保存 30 天。
- 实时状态、进程采样、空闲预约和远程结束进程行为不受远端历史同步影响。

### 验证记录

- 前端单元与组件测试 `42/42` 通过。
- TypeScript `tsc --noEmit` 检查与 Vite 生产构建通过；构建保留既有的 500 kB chunk 体积提示。
- Rust 测试 `20/20` 通过，新增远端格式解析、30 天清理边界、敏感进程数据排除、SQLite 增量导入、同步游标和重复数据去重测试。
- 远端采集脚本与守护脚本均通过 `sh -n` 语法检查，`git diff --check` 通过。
- macOS Tauri Release App 构建通过，版本号为 `1.5.0`；ad-hoc 签名严格校验通过。
- DMG `RackTop_1.5.0_aarch64.dmg` 通过 `hdiutil verify`，重新挂载后的 App 签名与版本复验通过；SHA-256 为 `4e48f0ba314f8c6e750c10652c2fa061eee4f36a00ba828b66a2c5ae15dc4ba7`。
- 未在真实服务器安装或启动常驻进程，也未执行远端写入验证，避免在用户确认前修改服务器状态。

### 已知事项

- 远端守护进程目前依赖普通 Linux 用户会话可运行 POSIX shell，并通过 `nohup`（可用时配合 `setsid`）脱离 SSH 会话；真实服务器的长期存活行为仍待授权后验证。
- 使用密码认证且未将密码保存到系统安全凭据存储时，App 重启后的自动同步需要用户重新提供密码。
- Windows 安装包仍需在真实 Windows runner 上构建验证。

### 升级说明

可从 1.4.0 直接升级。旧服务器保持远端历史关闭，原有本地历史完整保留；用户可以逐台编辑服务器并明确启用远端持续采集。

## 1.4.0 — 资源历史热力图

- 修改时间：2026-08-04 04:18:00 +08:00
- 发布日期：2026-08-04
- 发布阶段：功能版本
- 桌面平台：macOS、Windows
- 升级类型：兼容更新；不需要迁移配置或历史数据

### 版本概述

RackTop 1.4.0 将单台服务器的历史页改为 GitHub contribution graph 风格的资源热力图。每列代表一天，每格代表连续 3 小时的平均值，CPU 和每张 GPU 独立显示，并可分别切换 UTL 与 MEM。本版本同时补齐 GPU 详情卡片底部的总 SM 统计。

### 新增功能

- 历史页按资源拆分为 1 个 CPU 热力图和 N 个 GPU 热力图，实际有几张 GPU 就显示几个 GPU 块。
- 热力图横向每列为 1 天，纵向固定为 `00–03 / 03–06 / … / 21–24` 八个三小时区间；颜色分级表示区间平均使用率。
- 每个资源块都有独立的 `UTL / MEM` 分段选择器；GPU 默认显示 `MEM`，CPU 默认显示 `UTL`。
- 格子悬停信息包含日期、三小时区间、平均百分比和样本数，无样本区间保持中性显示。
- Rust/SQLite 新增按本机时区对齐的三小时聚合查询，只向前端返回聚合后的 CPU/GPU UTL 与 MEM，避免载入 30–90 天的原始秒级样本。

### 优化内容

- GPU 详情卡片底部固定显示 `MBW / 温度 / 功耗 / 进程 / SM` 五项统计，总 `SM` 位于最右侧。
- 概览页与 GPU 详情页复用同一个总 SM 聚合函数；无进程采样时统一显示 `0%`。
- 五项数据使用独立的等分网格，不改变 CPU 详情的四列统计行。
- 30 天热力图在常用桌面宽度下使用响应式双列布局，窄窗口自动回退为单列；90 天数据可在块内横向滚动。
- 三小时平均值低于 `3%` 时归一为 `0%` 并使用中性灰色，表示未使用；无样本格子使用更浅的灰色，达到 `3%` 才进入资源强度色阶。

### 验证记录

- 已增加三小时日期网格、CPU/GPU 指标选择和颜色级别的前端测试。
- 已增加 SQLite 三小时区间聚合测试，覆盖 CPU UTL/MEM、GPU UTL/MEM 与样本数。
- 已增加总 SM 聚合测试，覆盖多进程求和、无采样回退为 `0%` 和上限限制。
- 前端单元与组件测试 `42/42` 通过；TypeScript 全量检查与 Vite 生产构建通过，仍有既有的 500 kB chunk 建议提示。
- Rust 测试 `17/17` 通过，包含真实 SQLite JSON 字段的三小时聚合查询。
- macOS Tauri Release App 构建通过，版本号为 `1.4.0`，ad-hoc 签名严格验证通过；DMG 生成并通过 `hdiutil verify`。
- 已在真实 A100 服务器检查 Release App：历史页显示 1 个 CPU 与 3 个 GPU 块，CPU 默认 UTL、GPU 默认 MEM；GPU 详情底部五项同排且 SM 位于最右。

### 已知事项

- Windows 安装包仍需在真实 Windows runner 上构建验证。

### 升级说明

可从 1.3.0 直接升级；热力图直接读取已有历史表并在查询时聚合，不修改数据库结构、SSH 配置或已保存的原始样本。

## 1.3.0 — 空闲算力预约提醒

- 修改时间：2026-08-04 03:47:35 +08:00
- 发布日期：2026-08-04
- 发布阶段：功能版本（正式定稿）
- 桌面平台：macOS、Windows
- 升级类型：兼容更新；启动时自动创建预约数据表，不修改现有服务器、筛选条件或历史曲线

### 版本概述

RackTop 1.3.0 为“寻找空闲算力”增加条件预约。用户可以保存当前 GPU、CPU、进程、型号、持续时间和标签条件；应用在后台继续监测，条件稳定满足后发送包含服务器名称与 GPU 编号的系统通知。本版本同时分离高频状态刷新和历史曲线采样，扩展 GPU/CPU 进程及父子关系显示，并修复空闲显存边界判断及无标签卡片高度不一致问题。

### 新增功能

- “空闲条件”标题栏在“重置”左侧增加“预约”入口；即使当前已有符合条件的 GPU，也可以创建预约。
- 预约支持名称、2 小时/今天/24 小时/一直有效期限，以及“通知一次并结束”或“通知后继续监测”两种策略。
- 当前已符合条件的 GPU 在创建时保存为已知基线，不会立即重复通知；新的符合设备或退出后再次符合的设备才会触发。
- “当前快照”预约必须连续满足 30 秒；选择 5/10/30/60 分钟持续条件时沿用对应历史窗口判断。
- 通知标题使用具体服务器显示名和 GPU 编号，例如“3 * A100 · GPU 2 预约条件已满足”；正文显示可用 GPU/CPU 内存和可选物理位置。
- 点击预约通知会打开对应服务器的 GPU 详情；顶部铃铛提供预约列表，可编辑、暂停、恢复或删除预约。
- 预约持久化到本地 SQLite，应用重启后仍可恢复；完全退出应用期间不执行监测。
- 进程采样同时采集 GPU 与 CPU 任务，并记录 PID、父 PID、用户、命令、CPU、内存和运行时间；CPU 区块只保留 RSS 内存严格大于 1 GB 的 GPU 直接子进程，以及当前有 CPU 占用且占用最高的 12 个非系统用户进程组主进程。
- CPU 任务统一过滤常见后台服务，包括 nvitop/nvtop、VS Code/Cursor Remote、Codex、Claude、JetBrains Remote、用户桌面与音频会话，以及 Tailscale、ZeroTier、OpenVPN、WireGuard、Clash/Mihomo、sing-box、V2Ray/Xray、Cloudflare Tunnel 等常见 VPN/代理进程。
- 服务器“概览”和“进程”页都按 GPU、CPU 两个上下排列的区块显示进程；关系标签可直接识别“GPU 0 · PID 21312 的子进程”，GPU 父进程一侧也会显示 CPU 子进程数量或 PID。
- 概览复用紧凑进程模块并限制每块前 5 行，完整进程页复用同一模块展示全部采集结果和统一详情检查器。
- 点击进程后，详情在所选行正下方内联展开，不再脱离上下文显示在 GPU 与 CPU 两个区块之后。
- GPU 表将设备编号与 PID 合并为 `GPU · PID` 首列，使关系、用户和命令列采用与下方 CPU 表一致的紧凑排布。
- GPU/CPU 进程表增加受控的远程结束入口：只有当前 SSH 用户自己的进程组主进程可以勾选，其他用户进程与子进程不提供结束操作。
- 结束进程采用两阶段确认；第二阶段必须输入目标 PID，显示的 PID 可点击自动复制并原位提示“已复制”。Rust 后端会重新核对远端进程所有者与进程组主进程身份，再依次发送 TERM、等待、KILL 并清理残留子进程。
- “当前进程”摘要显示总进程数，副文案明确区分 GPU 与 CPU 进程数量，避免将 `12 CPU` 误解为 CPU 核心数；设置项同步更名为“进程刷新”。
- GPU 进程采样增加 NVIDIA `pmon` 的进程级 SM 活跃率；概览 GPU 卡片在 MBW 右侧显示所有已采样进程汇总的 `SM` 百分比，未采样时显示 `0%`，选中 GPU 或展开进程详情可查看各 PID 的 SM 百分比。

### 优化内容

- “算力总览”服务器卡片与单台服务器“概览”页的 GPU/CPU 状态目标刷新间隔缩短到 0.5 秒；其他页面和后台窗口继续使用既有采样间隔。
- 高频状态采集通过独立标志跳过历史写入，曲线仍按服务器原采样间隔记录并读取。
- 有标签和无标签的空闲 GPU 卡片都保留固定标签区域，卡片内容顶部保持对齐。
- 进程表将命令设为弹性主列，GPU/PID、关系、用户、显存、CPU 与运行时间采用稳定列宽；左侧选择位与区块图标对齐，长命令优先使用此前空置的横向空间。

### 修复内容

- 空闲条件筛选与卡片显示统一使用 0.1 GB 精度；显示 40.0 GB 的设备在筛选 40 GB 时不再错误标记为不可用。

### 保持不变的行为

- 预约只负责监测和通知，不会锁定 GPU，也不能阻止其他用户使用资源。
- 高频状态刷新不增加历史曲线采样点，GPU 与 CPU 进程仍按独立的较慢间隔刷新。

### 验证记录

- 全部前端单元测试 35 项通过；其中包含 GPU/CPU 进程双向父子关系、上下区块组件结构，以及仅本人进程组主进程显示远程结束入口的资格测试。
- 已执行 `git diff --check`，当前差异未发现空白错误。

- 默认“总览”现在一次展示全部服务器的 GPU 与 CPU 摘要；移除重复的“GPU 总览”导航入口，服务器详情仍可从状态墙或服务器列表进入。
- 服务器概览按“核心数据、GPU 状态、CPU 状态、实时趋势、当前进程”组织，趋势图按 CPU UTL、GPU MEM、系统 MEM / SWP、GPU UTL 的阅读顺序排列。
- 历史样本新增逐 GPU 的显存利用率与 Swap 利用率数据；旧 SQLite 数据库启动时自动增加 `gpu_memory_json`、`swap_utilization` 字段并保留已有记录。
- SSH 快照新增真实 CPU 型号采集，为空闲 GPU 页面提供跨服务器 CPU 型号筛选。

### 优化内容

- GPU 信息层级调整为 MEM 优先、UTL 次之，并在卡片底部集中显示 MBW、功耗、温度和进程数量。
- GPU 状态卡片采用用户选定的“极淡底色”方案：蓝、橙、红状态统一使用 `10%` 彩色边框权重和 `0.8%` 背景混合，醒目的颜色只保留给具体数值和进度条。
- GPU 状态墙的设备行改为“设备、显存、GPU”阅读顺序；背景填充长度直接对应显存占用比例，低于 `1%` 保持中性，UTL 仅使用独立数字强调色且后台刷新不播放填充动画。
- 概览中的 CPU 状态改为与 GPU 同尺寸的小卡片，统一放入资源状态网格；按系统 MEM、CPU UTL、1/5/15 分钟负载与 Swap 的顺序展示，点击可进入 CPU 详情。
- GPU 详情在常规宽度下自动采用紧凑多列布局，窗口缩小时回退为单列；选择设备不会再改变卡片顺序或引发布局跳动。
- 总览瀑布流改用可测量的 CSS Grid，并明确左右列的排序阅读顺序；切换“GPU 数量”等排序后不会在 macOS 上退化为纵向堆叠。
- 全局资源摘要在中等窗口宽度下会将排序控件换行，避免“平均 GPU”等数值被压缩成省略号。
- 手动“刷新全部”与单服务器重连使用独立反馈状态，后台自动采样不再让刷新按钮持续旋转。
- 顶部固定标题栏改为清晰的不透明背景和浅色分隔线，移除毛玻璃与下沿渐隐，避免产生页面尚未滑到顶部的错觉。
- 实时趋势图在后台采样时静默更新，不再每 2 秒上下展开；仅用户手动刷新时保留 `180ms` 的短反馈动画。
- GPU MEM、系统 MEM 与 SWP 的悬浮提示同时显示利用率和已用/总量 GB；图表更新时完整替换数据序列，避免不同图表之间残留旧 GPU 图例。
- macOS 标题栏保留交通灯安全区；Dock 使用无透明外缘的 macOS 专用图标源，避免系统为传统透明图标添加白色底板。
- 筛选数字输入允许清空后重新输入，`0` 可删除，输入 `20` 不会形成 `020`；当前快照筛选即时返回，持续时间筛选才查询完整历史窗口。
- 空闲 GPU 结果同时展示“可用”和“不可用”两种状态：可用设备优先、不可用设备随后按可用显存排序，并以中性灰卡片弱化但保留完整数据和详情入口。
- 空闲条件按 GPU MEM、CPU MEM、进程占用、GPU 型号、CPU 型号、持续时间、服务器标签排列；移除 GPU UTL 条件，进程占用只保留“不限”和“无人占用”，默认选择“无人占用”。
- 其他用户训练占用会忽略 `gdm`、显示服务、桌面合成器与 NVIDIA 常驻服务；其余进程合计不超过 GPU MEM `3%` 时也按未占用处理。

### 修复内容

- 修复日志、连接和 CPU“系统资源”模块标题或底部内容贴边、裁切及长文本溢出问题。

- 修复百分比异常值与平滑曲线过冲造成 GPU 利用率超过 `100%` 的显示问题。

## 0.1.0 — 首个 MVP 版本

- 发布日期：2026-08-03
- 发布阶段：MVP / 内部预览
- 桌面平台：macOS、Windows
- 技术栈：Tauri 2、React、TypeScript、Rust、SQLite

### 版本概述

RackTop 0.1.0 提供无需在远程服务器安装 Agent 的多服务器 GPU 监控体验。应用通过本机 OpenSSH 并发连接 Linux 服务器，在一个桌面界面中查看 GPU、CPU、系统负载、进程和历史趋势，并帮助用户快速找到空闲 GPU。

### 核心功能

- 添加、编辑、删除和搜索服务器，支持从 OpenSSH Config 导入配置。
- 支持 SSH Agent、私钥、密码、`~/.ssh/config`、ProxyJump 和 Host Key 指纹核验。
- 并发采集多台服务器，提供手动刷新、自动刷新、后台降频、失败重试和离线状态判断。
- 查看 GPU 利用率、显存、温度、功耗，以及 CPU、内存、Swap 和 Load。
- 查看 GPU 进程的用户、PID、命令、显存、CPU 占用和运行时长，并突出当前 SSH 用户。
- 将所有服务器组织为 GPU 状态墙：一台服务器一个瀑布流区块，仅展示 GPU 与 CPU 摘要，点击区块进入服务器详情。
- GPU 状态墙支持按名称、状态、GPU 数量、利用率或空闲数量排序，并记住用户的排序设置。
- 空闲 GPU 页面支持按利用率、可用显存、持续时间、GPU 型号和服务器标签筛选。
- 使用 SQLite 保存历史数据，支持趋势图、自定义采样间隔、趋势窗口和历史保留期。
- 支持系统托盘和桌面通知，可提示服务器离线、GPU 高温、GPU 空闲、显存释放、持续满载和任务退出。
- 支持跟随系统的浅色/深色主题、减少动效和当前用户强调色。
- 浏览器开发模式内置双服务器演示数据，便于不连接真实服务器时进行本地界面验证。

### 本版本优化与修复

- 修复数字筛选输入无法删除 `0` 的问题，清空后可直接输入新数值，例如 `20`，不会变成 `020`。
- 空闲 GPU 筛选默认使用当前快照即时返回；只有持续时间条件需要查询历史窗口。
- 修复筛选结果短暂出现后消失的问题，筛选条件在数据刷新期间保持有效。
- GPU 状态墙以显存占用作为卡片背景的主要状态语义，GPU 核心利用率仅作为辅助数值强调。
- 显存占用低于 `1%` 时按未使用处理并显示为 `0%`，使用中性背景，避免少量系统进程造成误判。
- 显存占用 `1%–49%` 使用蓝色提示，`50%–84%` 使用橙色提示，`85%–100%` 使用红色提示。
- 对采集到的百分比进行 `0%–100%` 边界限制，避免界面显示异常数值。

### 详情与连接能力

服务器详情包含概览、GPU、CPU、进程、历史、日志和连接页面。Host Key 未确认时不会自动接受；指纹发生变化时会阻止连接。密码不会写入命令行、日志或 SQLite，只保存在当前会话内存或系统凭据存储中。

当 Ubuntu/Debian 服务器缺少 NVIDIA 驱动时，RackTop 可以提供诊断和安装协助。应用不会自动执行 `sudo`，只有在用户连续确认后才会尝试通过免交互 `sudo -n` 安装。
