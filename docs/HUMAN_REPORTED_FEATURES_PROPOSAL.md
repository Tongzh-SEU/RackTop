## 2. 总体信息架构

服务器详情页的默认页签顺序调整为：

1. 概览
2. 进程
3. 终端（macOS）/ 命令行（Windows）
4. GPU
5. CPU
6. 历史
7. 连接

日志不再占用详情页页签。它移动到详情页右上角、设置按钮左侧，以 `ScrollText` 图标打开独立的非阻塞日志窗口。日志窗口不遮断主监控流程，并保留现有日志内容和自动滚动能力。

## 3. 用户占用华夫饼图

### 3.1 页面结构

“历史”页面在同一页面上下排列两个区块：

- 资源热力图：保留现有按 GPU/CPU 展示的热力图，位于上方。
- 使用分布图：新增两张左右排列的华夫饼图，窄窗口下改为上下排列，位于资源热力图下方。

两部分同时展示，不再通过二级切换控件二选一；使用分布时间范围只影响下方使用分布区块。

两张图分别表示：

- 使用时间：每个用户在所有 GPU 上的活跃时间，占“GPU 数量 x 时间范围”的比例。
- 显存占用：每个用户在所有 GPU 上的显存占用积分，占“总显存 x 时间范围”的比例。

未使用部分使用低透明度中性灰。图下方用颜色标签标识用户，并同时显示百分比，不能只依赖颜色传达信息。

### 3.2 时间范围

支持 1 周、半个月、1 个月、3 个月，默认 1 个月。

- 远端采集文件只保留最近 30 天。
- 本地 SQLite 同步后保留最近 90 天。
- 3 个月视图展示本地实际存在的数据，并显示“已覆盖 X / 90 天”。
- 本地超过 30 天未打开时，远端无法补回更早的数据；界面必须明确显示覆盖缺口，不用零值伪装缺失数据。

### 3.3 数据与隐私

为支持用户标签，远端新增按时间桶聚合的用户 GPU 使用数据。只保存：

- 时间桶；
- GPU UUID 或稳定索引；
- Unix 用户名；
- 活跃秒数；
- 显存使用量的聚合值；
- 采样覆盖量。

不保存 PID、命令、命令参数、终端输入输出或文件路径。同步到本地后按 90 天清理，远端按 30 天清理。

系统显示服务和常见监控守护进程不计入用户占用。过滤以明确的系统用户、进程类型和可维护规则为基础；无法确认归属的数据计入“其他”，不错误归给某个用户。

## 4. 完整 SSH 终端

### 4.1 体验

终端页打开后自动连接当前服务器，提供接近系统终端的持续会话：

- ANSI 颜色和光标控制；
- 交互式输入及历史；
- `Ctrl+C` 等控制键；
- 终端尺寸变化同步到远端 PTY；
- 连接中、已连接、断线和重连状态；
- 明确的关闭会话操作。

切换服务器时不会把命令发送到错误服务器。删除服务器、退出应用或主动关闭终端时，关闭相应会话。RackTop 不记录终端输入和输出。

### 4.2 技术路线

- 前端使用 `xterm.js` 与 fit addon。
- Rust 使用 `portable-pty` 管理本地 SSH 子进程及其 PTY。
- SSH 参数复用现有连接配置，包括 Host Key 校验、ProxyJump、SSH Agent 和私钥。
- 密码认证继续使用现有安全凭据流程；持久终端优先推荐 SSH Agent。

终端是持久 PTY 会话，不使用一次性 `ssh <host> <command>` 模拟。

## 5. 空闲算力快捷终端与预约

### 5.1 卡片交互

- 点击可用 GPU 卡片主体：打开固定到该 GPU 的快捷终端。
- 点击卡片右上角箭头：进入服务器详情页。
- GPU 不可用时：右上角显示预约按钮，点击后预约该 GPU。

### 5.2 GPU 固定与检测

快捷终端建立后先执行：

```sh
export CUDA_VISIBLE_DEVICES=<目标 GPU 索引>
```

发送命令前检查命令中的 `CUDA_VISIBLE_DEVICES`：

- 明确的数字或数字列表与目标 GPU 冲突时，自动替换为目标索引，并在发送前给出醒目但不打断操作的提示。
- 简单变量赋值可追踪到明确数字时，按解析结果检查。
- 变量、命令替换或复杂 Shell 表达式无法静态判断时，不静默改写；要求用户确认后发送。
- 检测器只处理环境变量赋值，不对普通命令文本进行全局字符串替换。

## 6. GPU / CPU 短期趋势

GPU 和 CPU 页的每个趋势块增加两个分段控件：

- 时间范围：1 小时、3 小时、1 天、3 天，默认 3 小时。
- 指标：UTL、MEM。

切换只改变当前趋势块，不影响历史热力图默认值。数据不足时显示实际覆盖范围，不拉伸或复制数据填满选定时间。

## 7. 添加服务器新手引导

首次进入添加服务器流程时显示紧凑的分步提示，重点说明：

- 地址、用户名和认证方式的含义；
- 如何快速配置 SSH 密钥；
- 首次 Host Key 确认；
- 远端持续保存和同步的作用。

SSH Agent 标记为“推荐”，并说明它支持安全复用凭据和持久终端，无需在 RackTop 中反复输入密码。引导提供“不再提醒”，只在用户主动勾选并成功保存后记住；设置中提供重新开启入口。

高亮只用于当前步骤，不持续闪烁，并遵循系统减少动态效果设置。

## 8. 系统菜单栏预约摘要

托盘菜单精简为：

1. 打开 RackTop
2. 预约摘要
3. 退出

预约摘要记录三类数量：等待中、当前可用、待确认。菜单栏扩展文本仅在存在待处理预约时显示，例如“预约 3 · 可用 1”；没有待处理事项时只显示图标。

生命周期规则：

- 条件未满足：等待中。
- 连续满足约 30 秒：进入当前可用，并产生一次通知。
- 后续重新不可用：保留“曾满足、待确认”记录，避免用户错过；同时标明当前已不可用。
- 用户打开摘要并明确清除：结束该条菜单栏提示。
- 用户取消预约：立即移除等待状态，但不自动删除已经产生的待确认记录。

状态持久化到本地数据库，应用重启后继续有效。

- RackTop 名称和当前版本；
- 简短产品说明；
- 作者头像与作者名称；

头像在构建时作为本地资源打包，About 打开时不依赖网络。外部链接必须由用户点击后才打开。

## 10. 实施与验收顺序

用户确认本方案后按依赖关系实施：

1. 数据库迁移、远端用户聚合采集和 30/90 天清理规则；
2. 用户占用视图与数据覆盖提示；
3. SSH PTY 后端和终端页；
4. 空闲 GPU 快捷终端及命令检测；
5. GPU/CPU 短期趋势控件；
6. 新手引导、托盘预约摘要、About 和日志窗口；
7. 网页端功能与视觉验证；
8. 最后统一执行一次 Rust/Tauri App 构建与本地运行验证。

新功能验收前不会用静态占位数据冒充远端采集结果，也不会因 3 个月数据缺失而显示虚假的零使用率。
